# DD-07 约束收集与多人聚合 · 详细设计

**详细设计系列 · 领域节点文档 · v1.0 · 2026 年 7 月**

> 本文定义规划流的**入口节点** `parse`（ConstraintParser）与**多人聚合**能力：把用户自然语言 + 各同行人脱敏约束，转换成 DD-01 §8.1 权威 `plans.constraints` schema（含供 DD-05 检索的 `query`），并在缺失关键约束时**主动追问补全**（UI 克制：选择题/短文本）。它是全链路的"约束事实源"，但**自身不产对外事实**，故不受 DD-03 Provenance Guard 约束。
>
> **上游依据**：DD-01（`plans`/`plan_members`/`party_constraints`/`user_context` 表、§8.1 `constraints` schema、§11 隐私）、DD-02（`parse` 节点契约：读 constraints(原始)/party，写 constraints(结构化)/warnings）、DD-04（LLM 路由 `constraint_parse=qwen-plus`、`redact()` 脱敏、禁止裸调）、DD-05（消费 `constraints.query` 与结构化过滤字段）、v1 §5.1/§6.4/§9.9、两份 PRD（约束收集、匿名邀请、只展示聚合结果）。
> **下游消费者**：DD-02（`parse` 节点宿主）、DD-08（`discover` 读 constraints）、DD-09（`transport` 读 constraints）、DD-05（`research`/`dining` 读 `constraints.query` 与过滤字段）、DD-13（分享卡展示聚合视图）。
> **本文约定**：金额单位**元**（对齐 DD-01 §8.1 `budget_band` 与 `user_context.budget_band`，注意与回填域的"分"区分）；时间统一 `TIMESTAMPTZ`，展示层转 `Asia/Shanghai`；所有进 LLM 的 payload 先过 DD-04 `redact()`。

## 1. 模块职责与边界

| 项 | 说明 |
|---|---|
| **职责** | ① 实现 DD-02 图的 `parse` 节点：自然语言 + 原始约束 → DD-01 §8.1 结构化 `constraints`；缺关键约束时生成**追问项**（选择题/短文本），补全后回灌；产出 `constraints.query`（供 DD-05）。② 提供**多人聚合**：匿名邀请令牌、各同行人独立回填 `party_constraints`（脱敏落库）、`aggregate_party` 聚合算法与公平性计算，产出匿名 `plans.constraints` 与 `party`（脱敏视图）。 |
| **边界内** | `parse` 节点函数、`ConstraintParser` 解析/追问逻辑与 prompt、结构化 schema 校验（Pydantic）、`aggregate_party`/`intersect_bands`/`commute_fairness` 算法、邀请/回填 API（BFF 侧路由契约）、缺省与降级策略、`plans`/`plan_members`/`party_constraints`/`user_context` 的**写入**。 |
| **边界外** | 城市打分（DD-08）、交通/门到门（DD-09）、检索算法（DD-05）、编排流转/中断恢复（DD-02）、LLM 客户端与脱敏中间件实现（DD-04）、表结构本身（DD-01）。本文只定义"如何把约束填进 DD-01 定义的形态"。 |
| **架构位置** | v1 §4.1 编排层的首个领域节点（v1 §5.1 [1] ConstraintParser）；数据归属矩阵中 `users/user_context/plans/plan_members/party_constraints` 的**写入方**（DD-01 §13）。 |

**设计原则**：① 约束是"事实的输入"而非"对外事实"——`parse` 只做结构化与补全，不给任何字段贴 `evidence` 六态（不受 Guard）；② 隐私最小化落到聚合层——个体精确预算/门牌**不外显**，只落脱敏粒度与聚合值（DD-01 §11.1）；③ 效果优先、前端克制——追问用有限选择题/短文本，不做花哨向导；④ v0.1 单组织者可跑，多人为 v0.2，但数据模型与聚合算法本文一并定义。

## 2. 设计目标与非目标

**目标**：
1. **对齐契约**：产出 100% 符合 DD-01 §8.1 的 `plans.constraints`，字段不多不少不改名；`parse` 的读写字段与 DD-02 §5 契约表一致。
2. **补全率**：关键约束（出发地、时间窗、预算、是否接受飞机）缺失时主动追问，一轮追问后补全率高（§11 指标）。
3. **可检索**：产出高质量 `constraints.query`（自然语言），直接喂 DD-05 稠密/稀疏召回 + 重排。
4. **多人隐私**：聚合后个体预算与精确地址**不可反推**；分享/state 快照默认只见聚合值与 `anon_label`。
5. **可降级**：LLM 不可用或追问未答齐 → 规则模板解析 + 带缺省 + `warning`，链路继续不阻塞（对齐 DD-02 §10）。

**非目标**：
- ❌ 不产生对外事实、不写 `evidence`、不参与 Guard 三闸（DD-03）。
- ❌ 不做对话式自由多轮 Agent；追问是**有界的结构化补全**（最多 N 项、UI 克制）。
- ❌ 不做交易、不采集精确 PII（门牌/证件/手机号），不落库个体精确预算明文。
- ❌ v0.1 不上 OR-Tools；公平性只做"通勤成本方差 + 标出最高成本者"的轻量诊断（v1 §9.9）。

## 3. 数据模型（引用 DD-01，不另立）

本模块**只写不改** DD-01 已定义的表。相关表与字段以 DD-01 为准，这里只列**写入职责与取值约定**：

### 3.1 写入的表（DD-01 §6）

| 表 | 本模块写入字段 | 取值/脱敏约定 |
|---|---|---|
| `users` / `user_context` | `home_cities` `budget_band` `prefer_flight` `accept_night_train` `interests` `dietary` | 显式授权后保存；作为**追问缺省**来源（老用户免重复问）；`budget_band` 单位元。 |
| `plans` | `organizer_user_id` `stage='explore'` `thread_id='plan:{id}'` `constraints`（§8.1）`weekend_start` `weekend_end` | `constraints` = 聚合后**匿名**约束；`weekend_*` 由目标周末解析得到（本地周五起）。 |
| `plan_members` | `invite_token` `anon_label`（"同伴A"）`is_organizer` `joined_at` | v0.1 仅组织者一条 `is_organizer=TRUE`；`invite_token` 最小权限、可过期（Redis `invite:{token}`）。 |
| `party_constraints` | `origin_area`（商圈级）`origin_geo`（商圈中心）`earliest_depart` `latest_return` `budget_band`（个体，仅聚合）`prefer_flight` `accept_night_train` `prefs` `dietary` | **脱敏落库**：`origin_area`="上海·徐汇" 商圈级而非门牌；`origin_geo` 存商圈中心坐标；`budget_band` 个体值默认不外显。 |

### 3.2 `plans.constraints` 权威 schema（DD-01 §8.1，本模块产出）

`parse`/`aggregate_party` 的最终产物就是这份 JSONB，**字段严格对齐 DD-01 §8.1**：

```jsonc
// plans.constraints —— DD-07 产出、DD-02 parse 写出、DD-05/08/09 读入
{
  "party_size": 3,
  "origins": ["上海·浦东", "上海·徐汇", "苏州"],          // 商圈级（脱敏），来自各 party_constraints.origin_area
  "earliest_depart": "2026-07-24T18:00:00+08:00",         // = 各人 earliest_depart 取 max（迁就最晚能走的）
  "latest_return":   "2026-07-26T22:00:00+08:00",         // = 各人 latest_return   取 min（迁就最早要回的）
  "budget_band": {"min": 1800, "max": 2600},               // 区间交集，单位元（人均）
  "accept_flight": true,                                    // = all(各人 prefer_flight/accept_flight)
  "accept_night_train": false,                              // = all(各人 accept_night_train)
  "interests": ["展览", "演出"],                            // 各人 prefs 并集去重
  "dietary": ["不吃辣"],                                    // 各人 dietary 并集去重
  "hard_constraints": ["周日must回上海"],                   // 硬约束（自由文本，原样保留供 validate/展示）
  "query": "本周末 展览 城市文化"                           // 供 DD-05 检索的自然语言查询
}
```

> **契约铁律**：本 schema 与 DD-01 §8.1 完全一致，不得增删字段或改名。如需新字段，先回改 DD-01 §8.1 并通知下游（DD-02/05/08/09），不得私自扩展。

### 3.3 `TripPlanState` 相关字段（DD-02 §3）

`parse` 节点在 `TripPlanState` 上的读写（严格对齐 DD-02 §5 契约表）：

- **读入**：`constraints`（原始，组织者自然语言 + 已知字段）、`party`（各同行人脱敏约束列表）。
- **写出**：`constraints`（结构化，§3.2 schema）、`warnings`（`Annotated[list[str], operator.add]`，缺省/降级说明）。
- **不写**：任何带 `evidence` 的事实字段（`parse` 不产事实）。

## 4. 接口契约

### 4.1 `parse` 节点函数签名（DD-02 图节点）

```python
from typing import TypedDict
from app.planner.state import TripPlanState        # DD-02 §3

async def constraint_parser(state: TripPlanState) -> dict:
    """DD-02 图的 parse 节点：读 constraints(原始)/party → 写 constraints(结构化)/warnings。
    不产对外事实，不受 DD-03 Guard。追问不全时带缺省 + warning 继续（DD-02 §5/§10）。
    返回的 dict 仅含被本节点写出的 state 字段（LangGraph 增量合并）。
    """
    raw: dict        = state.get("constraints", {}) or {}
    party: list[dict] = state.get("party", []) or []

    parser = ConstraintParser()
    if party:                                   # 多人（v0.2）：先聚合再补全
        agg, party_view, warns = await parser.parse_multi(raw, party)
    else:                                       # 单组织者（v0.1）
        agg, warns = await parser.parse_single(raw)

    return {"constraints": agg, "warnings": warns}
```

> `parse` 节点**不发起交互式追问**（LangGraph 节点内不阻塞等用户）。追问的产品语义走 BFF 层的"约束收集"环节（§4.3 `POST /plans` 之前的补全轮），补齐后才 `invoke(graph)`；节点内 `parse` 只做"尽力结构化 + 缺省 + warning"。这与 DD-02"LLM 不驱动流程"一致。

### 4.2 `ConstraintParser` 类

```python
from pydantic import BaseModel

class ConstraintParser:
    def __init__(self, llm_task: str = "constraint_parse"):    # DD-04 路由 → qwen-plus
        self.llm_task = llm_task

    async def parse_single(self, raw: dict,
                           user_ctx: dict | None = None) -> tuple[dict, list[str]]:
        """单组织者：自然语言/半结构 → §3.2 constraints + warnings。
        user_ctx（DD-01 user_context）作为缺省来源。"""

    async def parse_multi(self, organizer_raw: dict,
                          party: list[dict]) -> tuple[dict, list[dict], list[str]]:
        """多人：组织者约束 + 各同行人脱敏约束 → 聚合 constraints、脱敏 party 视图、warnings。"""

    def missing_slots(self, c: "ParsedConstraints") -> list["FollowUpQuestion"]:
        """检查关键约束缺口，产出有界追问项（选择题/短文本），供 BFF 收集环节使用。"""

    def build_query(self, c: "ParsedConstraints") -> str:
        """由 interests/hard_constraints/时间窗构造 constraints.query（供 DD-05）。"""
```

### 4.3 邀请 / 回填 API（BFF 侧路由契约，v0.2）

多人协作的 REST 契约（BFF 实现，DD-07 定义语义；令牌校验用 Redis `invite:{token}`，DD-01 §9.1）：

| 方法 | 路径 | 说明 | 请求体（脱敏后） | 返回 |
|---|---|---|---|---|
| POST | `/plans/{id}/invites` | 组织者生成匿名邀请令牌（可设过期/人数上限） | `{"expires_in": 86400, "max_uses": 5}` | `{"invite_token", "invite_url", "anon_label"}` |
| GET | `/invite/{token}` | 校验令牌 → 返回该 plan 的**填写表单 schema**（不含他人数据） | — | `{"plan_id", "form_schema", "anon_label"}` |
| POST | `/invite/{token}/constraints` | 同伴提交自己的脱敏约束（写 `party_constraints`） | `PartyConstraintInput`（§4.4） | `202`；不回显他人/聚合明细 |
| GET | `/plans/{id}/party/aggregate` | 组织者/成员查看**聚合视图**（默认只展示聚合值 + `anon_label`） | — | `{"constraints"(§3.2), "party_view"}` |
| DELETE | `/plans/{id}/invites/{token}` | 组织者失效某令牌 | — | `204` |

> **隐私铁律**：`/invite/{token}/constraints` 提交的 `origin`/`budget` 在**入库前**经 `redact()`（DD-04）降为商圈级 / 区间；`/party/aggregate` 默认**只返回聚合值**，个体 `budget_band` 与精确坐标不出接口（DD-01 §11.1，v1 §6.4）。

## 5. 核心算法

### 5.1 约束解析 prompt（LLM = qwen-plus，经 DD-04）

**调用纪律**：经 DD-04 `get_llm("constraint_parse")`（→ qwen-plus），进模型前 payload 过 `redact()`；用 PydanticAI / Function Calling 强制结构化输出 `ParsedConstraints`（不裸调、不自由文本解析）。

**结构化输出 schema（Pydantic，解析中间态）**：

```python
from pydantic import BaseModel, Field
from datetime import datetime

class BudgetBand(BaseModel):
    min: int | None = None      # 元
    max: int | None = None

class ParsedConstraints(BaseModel):
    """LLM 解析中间态；补全 + 校验后映射为 DD-01 §8.1 constraints。"""
    party_size: int | None = None
    origins: list[str] = []                     # 商圈级；缺则追问
    earliest_depart: datetime | None = None
    latest_return: datetime | None = None
    budget_band: BudgetBand = Field(default_factory=BudgetBand)
    accept_flight: bool | None = None
    accept_night_train: bool | None = None
    interests: list[str] = []
    dietary: list[str] = []
    hard_constraints: list[str] = []
    # query 不由 LLM 直接产，由 build_query() 确定性拼装（可控、可回归）
```

**System prompt（要点固化，禁编造）**：

```text
你是"周末去哪儿"的约束解析器。任务：把用户关于本周末跨城出行的自然语言，抽取为结构化 JSON，
严格符合给定 schema。规则：
1) 只抽取用户明确表达或可安全推断的字段；不确定就留空（null/空数组），绝不编造时间、预算或地点。
2) 出发地只到"城市·商圈"粒度（如"上海·徐汇"），不要门牌/小区名（已脱敏）。
3) 预算理解为人均预算区间（元）；只说"两三千"→ {min:2000,max:3000}；只说一个数→按 ±15% 给区间。
4) 时间窗：earliest_depart=最早可出发，latest_return=最晚须返回；相对表达（本周五晚）按提供的 weekend_start/weekend_end 归一为带时区时间。
5) interests/dietary 提取为短标签数组；hard_constraints 保留用户原话短句（如"周日必须回上海"）。
6) 不做行程规划、不推荐城市、不生成 query。只做抽取。
输出：仅 JSON，符合 ParsedConstraints schema。
```

**User prompt 模板**：

```text
weekend_start={weekend_start} weekend_end={weekend_end}
已知偏好(可空,来自历史)={user_ctx_json}
用户输入：""" {redacted_user_text} """
```

### 5.2 追问逻辑（缺失补全，UI 克制）

**关键约束缺口检测**：按优先级检查，缺失即生成**有界追问项**（最多 4 项，选择题优先，文本兜底）。追问在 BFF"约束收集"环节完成，补齐后才 `invoke(graph)`；节点内若仍缺则走缺省（§8）。

```python
REQUIRED_SLOTS = ["origins", "time_window", "budget_band", "accept_flight"]

class FollowUpQuestion(BaseModel):
    slot: str                       # origins/time_window/budget_band/accept_flight/...
    prompt: str                     # "你们大致从哪个城市/商圈出发？"
    input_type: str                 # "single_choice" | "multi_choice" | "text" | "date_range"
    options: list[str] = []         # 选择题选项（克制：3~5 个）

def missing_slots(self, c: ParsedConstraints) -> list[FollowUpQuestion]:
    qs: list[FollowUpQuestion] = []
    if not c.origins:
        qs.append(FollowUpQuestion(slot="origins",
            prompt="你们大致从哪个城市/商圈出发？", input_type="text"))
    if not (c.earliest_depart and c.latest_return):
        qs.append(FollowUpQuestion(slot="time_window",
            prompt="大致什么时候出发、什么时候要回？", input_type="date_range"))
    if c.budget_band.min is None and c.budget_band.max is None:
        qs.append(FollowUpQuestion(slot="budget_band",
            prompt="人均预算大概哪个区间？", input_type="single_choice",
            options=["1000 以内", "1000–2000", "2000–3000", "3000 以上", "不限"]))
    if c.accept_flight is None:
        qs.append(FollowUpQuestion(slot="accept_flight",
            prompt="接受坐飞机吗？", input_type="single_choice",
            options=["接受", "只坐高铁", "都行"]))
    return qs[:4]                    # 有界：一屏问完，不做多轮长对话
```

> **借鉴与克制**：借鉴马蜂窝 AI 路书"先主动提问/选择题补全"的思路提升成功率，但本阶段 **UI 克制**——不做花哨向导，一次性给出 ≤4 个选择题/短文本，答完即走。历史偏好（`user_context`）命中的槽位**不再追问**（老用户少打扰）。

### 5.3 `aggregate_party`（多人聚合，对齐 v1 §9.9）

```python
from datetime import datetime

def intersect_bands(bands: list[dict | None]) -> dict | None:
    """预算区间交集：min = max(各人 min)，max = min(各人 max)。"""
    valid = [b for b in bands if b and (b.get("min") is not None or b.get("max") is not None)]
    if not valid:
        return None
    lo = max((b["min"] for b in valid if b.get("min") is not None), default=None)
    hi = min((b["max"] for b in valid if b.get("max") is not None), default=None)
    if lo is not None and hi is not None and lo > hi:
        # 空交集：无法满足所有人 → 取"并集包络 + warning"（降级见 §8）
        lo = min(b["min"] for b in valid if b.get("min") is not None)
        hi = max(b["max"] for b in valid if b.get("max") is not None)
        return {"min": lo, "max": hi, "_conflict": True}
    return {"min": lo, "max": hi}

def aggregate_party(members: list[PartyConstraint]) -> dict:
    """聚合各同行人约束 → DD-01 §8.1 constraints（匿名）。仅返回聚合值。"""
    if not members:
        return {}
    origins = _dedup([m.origin_area for m in members if m.origin_area])       # 商圈级
    budget  = intersect_bands([m.budget_band for m in members])
    return {
        "party_size": len(members),
        "origins": origins,
        # 迁就"最晚能走的"取 max、"最早要回的"取 min → 全员可行
        "earliest_depart": max(m.earliest_depart for m in members).isoformat(),
        "latest_return":   min(m.latest_return   for m in members).isoformat(),
        "budget_band": {k: v for k, v in (budget or {}).items() if not k.startswith("_")} or None,
        # 只要有一人不接受，就不默认接受（保守，全员可行）
        "accept_flight":      all(bool(m.prefer_flight)      for m in members),
        "accept_night_train": all(bool(m.accept_night_train) for m in members),
        "interests": _dedup([p for m in members for p in m.prefs]),           # 并集去重
        "dietary":   _dedup([d for m in members for d in m.dietary]),         # 忌讳并集（从严）
        "hard_constraints": [],       # 由组织者/解析补充，非从个体聚合
        "query": "",                  # 由 build_query() 填充（§5.5）
    }

def _dedup(xs: list[str]) -> list[str]:
    seen, out = set(), []
    for x in xs:
        if x and x not in seen:
            seen.add(x); out.append(x)
    return out
```

> **聚合语义速查**：`earliest_depart=max`（迁就最晚能走的）、`latest_return=min`（迁就最早要回的）、`budget_band=区间交集`、`accept_flight=all`、`accept_night_train=all`、`interests/dietary=并集去重`（忌讳从严）。空交集/时间窗倒挂由 §8 降级处理并 `warning`。

### 5.4 公平性计算（通勤成本方差，v0.1 轻量）

不引入 OR-Tools（v0.2+ 才按需）；v0.1 只做"到候选枢纽的通勤成本诊断"，辅助"分别出发 / 目的地集合"决策（v1 §9.9）。通勤耗时经 DD-04 高德 `distance_matrix`（不裸调）。

```python
def commute_fairness(members: list[PartyConstraint],
                     hub: tuple[float, float]) -> dict:
    """各人商圈中心 → 枢纽(hub) 的通勤成本(分钟)，算方差并标出最高成本者。
    hub 通常为候选城市的主要车站/机场（DD-08/DD-09 提供）。"""
    costs = []
    for m in members:
        if not m.origin_geo:
            continue
        minutes = estimate_commute_minutes(m.origin_geo, hub)   # 经 DD-04 amap distance_matrix
        costs.append({"anon_label": m.anon_label, "minutes": minutes})
    if not costs:
        return {"variance": None, "max_cost_member": None, "detail": []}
    vals = [c["minutes"] for c in costs]
    mean = sum(vals) / len(vals)
    variance = sum((v - mean) ** 2 for v in vals) / len(vals)
    worst = max(costs, key=lambda c: c["minutes"])
    return {
        "variance": round(variance, 1),
        "mean_minutes": round(mean, 1),
        "max_cost_member": worst["anon_label"],   # 只暴露匿名标签，不暴露地址
        "detail": costs,                            # [{anon_label, minutes}]，无坐标
    }
```

> **公平性只做诊断不做最优化**：输出"谁通勤成本最高（匿名标签）+ 方差"，供组织者判断是否"分别出发"或换枢纽；不自动改约束。`detail` 只含匿名标签与分钟数，**不含坐标**（隐私）。

### 5.5 `build_query`（产出 constraints.query，供 DD-05）

`query` 由**确定性拼装**（不靠 LLM，可控可回归），喂 DD-05 `retrieve_activities`（其 `rerank_query` 会再拼预算/忌讳，DD-05 §6）：

```python
def build_query(self, c: ParsedConstraints) -> str:
    parts = ["本周末"]
    parts += c.interests or ["城市文化", "展览", "演出"]      # 无偏好给通用探索词
    for h in c.hard_constraints:
        parts.append(h)
    return " ".join(dict.fromkeys(parts))       # 去重保序
```

> `query` 只放**语义检索词**（偏好/主题/硬约束关键词）；结构化过滤（城市、时间窗、预算、`center` 半径）由 DD-05 召回 SQL 从 `constraints` 其它字段读取，不塞进 `query`（DD-05 §5/§6）。

## 7. 证据与状态（parse 不产事实）

- **不产对外事实**：`parse` 输出的 `constraints` 是"用户输入的结构化表达"，**不是**需要证据背书的对外事实（无价格/时刻/余票/营业时间等强时效字段）。因此本节点**不调用** `enforce_provenance`/`validate_fact`，**不写任何 `evidence` 字段**，**不在 Guard 三闸范围内**（DD-02 §5 标注"受 Guard=否"；DD-03 §8 未列本模块）。
- **约束的可信来源**：约束值来自用户/历史偏好，天然是 `user_provided` 语义；但它们是"输入"而非"展示事实"，故不落六态。当这些约束被下游转化为**对外事实**（如 DD-08 城市卡的门到门耗时、DD-09 交通耗时），由**下游模块**按 DD-03 定级（`rule`/`amap`→`estimated`/`public_source_observed`）。
- **状态影响**：`parse` 只写 `constraints` 与追加 `warnings`；`plans.stage` 保持 `explore`（阶段流转由 DD-02 编排，不在本节点）。
- **可观测**：`parse` 一个 OTel span（DD-02 §12 / DD-04 §9），记录 token、追问项数、命中历史偏好数、降级标志；**不涉及** Guard 断言计数（那是 `compose` 的事）。

## 8. 降级（追问不全→带缺省 + warning）

对齐 DD-02 §5/§10：本节点**不整链失败**，缺则带缺省 + `warning` 继续。降级策略表：

| 场景 | 降级行为 | warning 文案（示例） |
|---|---|---|
| LLM 不可用 / 超时 | 走**规则模板解析**（正则/关键词抽时间地点、预算档位映射），不阻塞 | `"约束解析降级为规则模板，建议核对时间/预算"` |
| 追问未答齐 · 缺 `origins` | 用 `user_context.home_cities` 首项；再缺则不设，交 DD-08 做同城/近郊候选 | `"未提供出发地，已用历史常用出发地 上海·徐汇"` |
| 追问未答齐 · 缺时间窗 | 缺省为**目标周末**：`earliest_depart=周五18:00`、`latest_return=周日22:00`（本地时区） | `"未指定时间，默认周五晚出发、周日晚返回"` |
| 追问未答齐 · 缺 `budget_band` | 置 `null`；DD-08/09 按"不限预算但标注估算"处理 | `"未提供预算，结果不按预算过滤"` |
| 缺 `accept_flight`/`accept_night_train` | 缺省 `accept_flight=true`、`accept_night_train=false`（保守偏舒适） | `"未指定交通偏好，默认接受飞机、不安排夜车"` |
| 多人 · 预算**空交集** | `intersect_bands` 返回并集包络 + `_conflict`，聚合改用包络区间 | `"同行人预算无交集，已按最宽区间处理，建议协商"` |
| 多人 · 时间窗倒挂（max earliest > min latest） | 保留原值 + 强 `warning`，交 DD-12 `validate` 判不可行 | `"同行人时间窗不兼容：最晚出发晚于最早返回，需协商"` |
| 多人 · 某同伴缺 `origin_geo` | 该人跳过公平性计算，`commute_fairness` 仅算有坐标者 | `"部分同行人缺出发地坐标，公平性诊断不完整"` |

```python
DEFAULTS = {
    "weekend_depart_hour": 18,       # 周五 18:00
    "weekend_return_hour": 22,       # 周日 22:00
    "accept_flight": True,
    "accept_night_train": False,
}

def apply_defaults(c: ParsedConstraints, weekend: "Weekend",
                   user_ctx: dict | None, warns: list[str]) -> ParsedConstraints:
    if not c.origins and user_ctx and user_ctx.get("home_cities"):
        c.origins = [user_ctx["home_cities"][0]]
        warns.append(f"未提供出发地，已用历史常用出发地 {c.origins[0]}")
    if not c.earliest_depart:
        c.earliest_depart = weekend.friday.replace(hour=DEFAULTS["weekend_depart_hour"])
        warns.append("未指定时间，默认周五晚出发、周日晚返回")
    if not c.latest_return:
        c.latest_return = weekend.sunday.replace(hour=DEFAULTS["weekend_return_hour"])
    if c.accept_flight is None:
        c.accept_flight = DEFAULTS["accept_flight"]
        warns.append("未指定交通偏好，默认接受飞机、不安排夜车")
    if c.accept_night_train is None:
        c.accept_night_train = DEFAULTS["accept_night_train"]
    return c
```

> **降级铁律**：任何缺省都必须落一条 `warning`（前端可提示用户补充），保证"系统的假设对用户透明"。缺省绝不伪装成用户的明确选择。

## 9. 隐私与合规（脱敏、聚合、PIPL）

严格落实 DD-01 §11（隐私最小化 / PIPL）与 v1 §6.4（多人聚合隐私）、§7.2（脱敏与数据主权）：

1. **数据最小化**：`party_constraints.origin_area` 只存**商圈级**（"上海·徐汇"），`origin_geo` 存**商圈中心坐标**而非家庭门牌；证件/手机号**不落库**；个人精确预算以区间 `budget_band` 存、**默认不外显**（DD-01 §11.1）。
2. **进模型前脱敏**：所有进 LLM 的文本（组织者输入、同伴输入）先过 DD-04 `redact()`——门牌→商圈、证件/联系方式→打码、精确预算→区间；模型侧永不见原始 PII（DD-04 §6.2）。
3. **聚合而非明细**：系统持久化并对外展示的是**聚合结果**（`plans.constraints`）；`/party/aggregate` 默认只回聚合值 + `anon_label`；个体 `budget_band`、`origin_geo` **不出接口、不进分享卡**（v1 §6.4）。公平性 `detail` 只含匿名标签 + 分钟数，不含坐标。
4. **匿名邀请最小权限**：`invite_token` 可过期、可限用量（Redis `invite:{token}`）；同伴填写页只见**表单 schema 与自己的输入**，看不到他人数据与组织者明细。
5. **BYO Key 与数据主权**：用户可用自带模型 Key（DD-04 §6.3），走用户配额、服务端不落 Key 明文。
6. **用户数据权利**：本模块写入的 `user_context`/`plans`/`party_constraints` 均随 DD-01 §11.4 一键导出/删除（`ON DELETE CASCADE`）。同伴可请求删除自己的 `party_constraints` 行（聚合值随之重算）。

> **可反推风险防护**：当 `party_size` 很小（如 2 人）时，聚合值可能间接暴露个体（如预算交集=某人区间）。缓解：聚合展示只给**区间**不给精确值；`party_size≤2` 时预算展示进一步粗化为档位（"2000–3000"），并在文案标注"为保护隐私已模糊"。

## 10. 配置（LLM 成本）

| 配置项 | 值 | 说明 |
|---|---|---|
| LLM 路由 | `constraint_parse → qwen-plus`（DD-04 §6.1） | 中档：约束解析/追问；能规则解决的不调模型（先规则映射预算档位，再 LLM 补语义） |
| LLM 缓存 | 相同输入 24h（DD-04 §4.1） | 同一组织者短时间内重复提交命中缓存，省 token |
| 追问上限 | ≤4 项 / 轮，最多 1 轮 | UI 克制；答不齐走缺省（§8），不做多轮长对话 |
| `redact()` | 强制，边界统一执行 | BFF↔Planner 边界 + 每次 LLM 调用前（DD-04 §6.2） |
| 通勤估算 | 高德 `distance_matrix`，缓存 7d（DD-04 §4.1） | 公平性诊断用；超额降级为直线估算 + 标注（DD-04 降级链） |
| 预算档位映射 | 规则表（"1000 以内/1000–2000/…"→区间） | 选择题答案确定性转区间，不过 LLM |
| BYO Key | 支持（DD-04 §6.3） | 重度用户走自带配额 |

**成本控制要点**：约束解析是**低频**调用（一次规划一次；追问补齐后不重解析）；单次 payload 小；优先规则映射选择题答案。整体 LLM 成本占比低，主要成本在下游检索/抽取（DD-05/DD-06/DD-10）。

### 11.2 测试用例（pytest）

**单人解析**：
1. 完整输入（"我们3人从上海徐汇周五晚出发周日晚回，人均两三千，接受高铁不坐飞机，想看展览不吃辣，周日必须回上海"）→ 断言各字段正确映射、`origins=["上海·徐汇"]`（脱敏）、`budget_band={min:2000,max:3000}`、`accept_flight=false`、`hard_constraints` 含"周日必须回上海"、`query` 含"展览"。
2. 缺出发地 → `missing_slots` 返回 `origins` 追问项；补齐后重解析通过。
3. 缺预算 + 缺时间 → 走缺省，`warnings` 含两条缺省说明，`constraints` 仍可用。
4. LLM mock 抛错 → 规则模板解析，`warnings` 含降级说明，关键字段非空。
5. 门牌输入（"上海市徐汇区XX路123号"）→ `redact` 后 `origins` 只到"上海·徐汇"，无门牌泄漏。

**多人聚合**：
6. 3 人不同出发地/时间/预算 → 聚合值：earliest=最大、latest=最小、budget=交集、flight=all、interests 并集去重、dietary 并集。
7. 预算空交集（[1000,1500] ∩ [2500,3000]）→ 返回并集包络 + `_conflict`，`warnings` 含"无交集"提示。
8. 时间窗倒挂 → 保留原值 + 强 warning，`validate`（DD-12）可判不可行。
9. 隐私断言：`aggregate_party` 输出与 `/party/aggregate` 响应中**无** `origin_geo`、无个体 `budget_band`；`party_view` 只含 `anon_label` + 区间/商圈级。
10. `commute_fairness`：给定 3 人坐标 + 枢纽 → 方差正确、`max_cost_member` 为通勤最久者的 `anon_label`，`detail` 不含坐标。
11. 小团体（2 人）预算模糊化：`party_size=2` 时聚合预算展示为档位而非精确值。
