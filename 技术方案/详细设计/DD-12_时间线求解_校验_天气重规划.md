# DD-12 时间线求解 · 可行性校验 · 天气重规划 · 详细设计

**详细设计系列 · 领域节点文档 · v1.0 · 2026 年 7 月**

> 本文定义「周末去哪儿」的**质量闭环模块**：`timeline`（时间线求解）与 `validate`（可行性校验）两个 LangGraph 节点，以及**天气感知重规划**机制。这是产品差异化的落点——**逐小时可执行时间线**与**硬冲突率=0 的质量 KPI**都在这里兑现；天气作为**概率信号**参与排程与重规划。
>
> 产品硬约束在本模块的体现：① **不做交易**——只排程、不下单，票价/余票不生成；② **证据优先**——时间线槽位**不新造证据**，一律透传上游（bookings/activities/route_legs/dining_picks）已带的 `evidence`；③ **轻后端重证据**——周末只有两天、活动数量少，用**确定性贪心排点 + 硬约束校验**（不上重型求解器），可解释、可回退、可调试。
>
> **上游依据**：技术架构 v1（§9.5 时间线求解 `solve_timeline` + 可行性校验 `validate`、§9.6 天气重规划 `weather_replan`）、PRD 对外版（§5.9 天气感知与智能重规划、06 逐小时时间线、可信度指标"日程硬冲突率"）。
> **契约依赖**：DD-01（`timeline_slots` 表 §8.5、`slot_kind` 枚举 §4、`route_legs`/`dining_picks`/`bookings` 表 §8、evidence JSONB §5、归属矩阵 §13）、DD-02（`timeline`/`validate` 节点契约 §5、条件边 `route_after_validate` §4、重规划 `trigger_replan` §8、`TripPlanState` §3）、DD-03（`Fact/Evidence` 透传、无新造事实）、DD-04（和风天气 `weather_hourly`/`minutely_precip`/`warning`，禁裸调）、DD-10（`to_timeline_anchors`：train/flight/hotel 锚点，只读 `confirmed=True`）、DD-11（`route_legs` 接驳、`dining_picks` 饭点）、DD-08（`research` 选定活动）。
> **下游消费者**：DD-02（作为节点挂图 + 条件边驱动 + 重规划重入）、DD-13（消费 `timeline_slots` 渲染确认版 bundle 的逐小时时间线）。
> **一句话**：**从到达时刻起按开放时间与优先级贪心排点，逐段接驳推进游标，到饭点插餐，末尾加返程缓冲；校验硬约束驱动条件边回退；天气变化时只重算受影响子图，已确认 bookings 永不改动。**

## 1. 模块职责与边界

| 项 | 说明 |
|---|---|
| **职责** | 实现 DD-02 图上的 `timeline`（确定性贪心排点）与 `validate`（硬约束校验）两个节点；实现天气感知重规划的**动作计算与重入逻辑**（经 DD-02 `trigger_replan` 从 `timeline`/`dining` 重入）。 |
| **边界内** | ① 贪心排点算法（消费 bookings 锚点 + activities 选定 + route_legs 接驳 + dining_picks 饭点，产出 `timeline_slots`）；② 硬约束校验（overlaps/返程缓冲/营业时间/预算），产出 `validation{ok,issues}` 驱动条件边；③ 硬冲突率 KPI 埋点；④ 天气动作计算（降水/高温/预警）与重入时的受影响子图重算；⑤ 校验不过的回退重排策略。 |
| **边界外** | 交通锚点抽取（DD-10 `to_timeline_anchors`，本模块只消费）；接驳路段计算（DD-11 写 `route_legs`）；饭点候选生成（DD-11 写 `dining_picks`）；活动检索与选定（DD-05/DD-08）；天气 Provider 实现（DD-04，本模块只调 `ResilientProvider`，**禁裸调**）；条件边拓扑与 checkpoint（DD-02）；bundle 渲染（DD-13）。 |
| **架构位置** | v1 §4.1 编排层领域节点，§9.5/§9.6。挂在 DD-02 图 `dining → timeline → validate → compose` 链上，`validate` 出条件边。 |

**设计原则**：① **确定性可调试**——贪心 + 校验全程无 LLM，输入相同则输出相同（幂等，DD-02 §9），便于单测与回退；② **证据零新造**——槽位 `evidence` 一律透传来源实体的 `evidence`，本模块不构造任何 `verification_status`；③ **已确认不可动**——`bookings`（`confirmed_by_user`）锚点是排程的不可变边界，重规划只调整活动/餐饮/接驳，交通锚点恒定；④ **硬冲突率是硬 KPI**——`validate` 的 `HARD_CONFLICT` 计数直接进埋点，目标恒为 0。

## 2. 设计目标与非目标

**目标**：
1. **逐小时可执行**：输出精确到分钟的 `timeline_slots`（seq/start_at/end_at/kind/ref_table/ref_id/evidence），"到发站→进站→运行→接驳→活动→午餐→活动→晚餐→返程缓冲→返程"每段落地。
2. **硬冲突率=0**：任何时段重叠、营业时间违反、返程赶不上，都被 `validate` 捕获并经条件边回退重排，出稿前收敛为无硬冲突。
3. **天气参与排程**：天气作为概率信号影响活动排序（降水↑室外降权、高温减步行、预警去高风险户外），并在 72h/24h/手动触发时重规划。
4. **可回退可重入**：`validate` 硬冲突 → 条件边回 `timeline`（reflow）或 `transport`（retransport）；天气重规划从 `timeline`/`dining` 重入，只重算受影响子图。
5. **确定性可解释**：不上 OR-Tools/CP-SAT 等重型求解器（周末规模小），贪心即可，每个决策可追溯、可埋点。

**非目标**：
- ❌ 不做交易/下单/占座（PRD 硬约束一）——只排时间，不生成票价/余票。
- ❌ 不新造证据（硬约束二）——槽位证据全部透传上游实体。
- ❌ 不改动已确认 bookings——交通锚点是排程边界，重规划不动它。
- ❌ 不做多日复杂行程优化（周末 2 天，贪心足够）；不做全局最优 TSP（活动数 ≤ ~8，顺序由开放时间与优先级决定）。
- ❌ 不裸调天气 API（经 DD-04 `ResilientProvider`）。

## 3. 数据模型

### 3.1 `timeline_slots` 表（引用 DD-01 §8.5，本模块为唯一写入方）

DD-01 已定义 DDL，此处**不重复，只标注本模块的字段写入语义**：

| 字段 | 类型 | 本模块写入语义 |
|---|---|---|
| `plan_id` | BIGINT | 归属计划 |
| `seq` | INT (NOT NULL) | 时间线内顺序，从 0 递增；`UNIQUE(plan_id, seq)` |
| `start_at` / `end_at` | TIMESTAMPTZ | 槽位起止（UTC 存储，展示层转 `Asia/Shanghai`）；`buffer`/`free` 槽位可只有 `start_at` |
| `kind` | `slot_kind` = `transport`/`activity`/`meal`/`lodging`/`buffer`/`free` | 槽位类型，决定渲染与校验规则 |
| `ref_table` | TEXT | 回指来源表：`bookings`/`activities`/`dining_picks`/`route_legs`；`buffer`/`free` 为 `NULL` |
| `ref_id` | BIGINT | 来源表主键；`buffer`/`free` 为 `NULL` |
| `title` | TEXT | 展示标题（透传来源，如 "G7016 上海虹桥→苏州"、"苏州博物馆") |
| `evidence` | JSONB (NOT NULL) | **透传来源实体的 evidence，不新造**；`buffer`/`free`（系统估算）用 `rule → estimated`（DD-03 §4） |

> **kind → ref_table 映射**：`transport`→`bookings`(交通锚点) 或 `route_legs`(市内接驳)；`activity`→`activities`；`meal`→`dining_picks`；`lodging`→`bookings`(酒店锚点)；`buffer`→`NULL`（返程/进站缓冲，系统估算）；`free`→`NULL`（空闲/机动）。

## 5. 核心算法

### 5.1 贪心排点 `solve_timeline`（v1 §9.5 落地）

```python
# dd12/solver.py
from datetime import datetime, timedelta

DEFAULT_ACT_DURATION_MIN = 120        # 活动缺省时长（无明确时长时）
STATION_ARRIVAL_BUFFER_MIN = 25       # 进站/值机缓冲（返程用）
MEAL_DURATION = {"lunch": 60, "dinner": 75, "coffee": 40}
MEAL_WINDOWS = {"lunch": (11*60, 14*60), "dinner": (17*60, 20*60)}  # 本地分钟

def solve_timeline(bookings, activities, dining, local_routes, weather_actions=None):
    anchors = _collect_booking_anchors(bookings)         # DD-10 to_timeline_anchors 汇总排序
    routes  = _index_routes(local_routes)                # {(from_key,to_key): leg}
    acts    = _apply_weather(_select_activities(activities), weather_actions)  # 天气降权/替换（§5.3）

    slots, seq = [], 0
    # —— 1. 去程交通锚点（confirmed，不可动）——
    outbound = _arrival_anchor(anchors)                  # 最早的 transport 锚点
    if outbound:
        slots.append(_anchor_slot(seq, outbound)); seq += 1
        cursor = _Cursor(time=_iso(outbound["end_at"]), place=_anchor_place(outbound))
    else:                                                # 同城/无交通回填：从周末窗口起点开始
        cursor = _Cursor(time=_weekend_start(), place=_home_area())

    # —— 2. 入住锚点（若酒店 check_in 早于首个活动，先落 lodging 槽）——
    checkin = _lodging_anchor(anchors, "check_in")
    if checkin and _iso(checkin["start_at"]) <= cursor.time:
        slots.append(_anchor_slot(seq, checkin)); seq += 1  # 寄存/入住不推进 cursor（可并行）

    # —— 3. 活动按开放时间 + 优先级贪心排点，逐段接驳推进 cursor ——
    for act in _order_by_open_and_priority(acts):
        leg = _find_leg(cursor.place, act["location"], routes)   # DD-11 route_legs 查段
        transit = _transit_slot(seq, leg, cursor.time); seq += 1
        slots.append(transit)
        cursor.time = transit["end_at"]; cursor.place = act["location"]

        open_at, close_at = _open_window(act, cursor.time)       # 尊重营业/展期
        start = max(cursor.time, open_at)
        if start >= close_at:                                    # 到点已闭馆 → 跳过并 warn（validate 兜底 CLOSED）
            _warn(f"活动 {act['title']} 到达时已闭馆，跳过")
            slots.pop(); seq -= 1                                # 撤销无意义接驳
            continue
        dur = timedelta(minutes=_duration_min(act))
        end = min(start + dur, close_at)

        # 到饭点就在动线上插餐（插在活动之前，若当前时刻落在餐窗）——
        seq = _insert_meal_if_due(slots, dining, cursor, seq)

        slots.append(_activity_slot(seq, act, start, end)); seq += 1
        cursor.time = end; cursor.place = act["location"]

    # —— 4. 收尾：晚餐（若未插过且在餐窗）+ 返程缓冲 + 返程交通锚点 ——
    seq = _insert_meal_if_due(slots, dining, cursor, seq, force_slot="dinner")
    ret = _departure_anchor(anchors)                             # 返程 transport 锚点
    if ret:
        seq = _append_return_buffer(slots, cursor, ret, routes, seq)  # 接驳 + 进站缓冲
        slots.append(_anchor_slot(seq, ret)); seq += 1
    return slots
```

**关键子过程（真实可跑，其余同构）**：

```python
class _Cursor:
    def __init__(self, time, place): self.time, self.place = time, place

def _order_by_open_and_priority(acts):
    """先按最早开放时间升序（早开的先排），同组按优先级降序（rerank/官方确认高的优先）。"""
    return sorted(acts, key=lambda a: (_open_at_local(a), -a.get("_priority", 0.5)))

def _find_leg(from_place, to_place, routes):
    """从 DD-11 route_legs 索引查接驳段；查不到 → 规则兜底（直线速度估，估算态）。"""
    leg = routes.get((_geo_key(from_place), _geo_key(to_place)))
    if leg:
        return leg
    minutes = _straight_line_minutes(from_place, to_place)       # haversine / 平均速度
    return {"minutes": minutes, "mode": "estimate",
            "evidence": {"source_type": "rule", "verification_status": "estimated",
                         "note": "无匹配路段，直线估算"}}

def _transit_slot(seq, leg, start_time):
    end = start_time + timedelta(minutes=leg["minutes"])
    return {"seq": seq, "start_at": end - timedelta(minutes=leg["minutes"]), "end_at": end,
            "kind": "transport", "ref_table": ("route_legs" if leg.get("id") else None),
            "ref_id": leg.get("id"), "title": _leg_title(leg),
            "evidence": leg["evidence"], "_place": leg.get("to_geo")}

def _insert_meal_if_due(slots, dining, cursor, seq, force_slot=None):
    """当前 cursor 时刻落在餐窗且该餐未安排 → 从 dining_picks 选最近饭点插餐。"""
    slot_name = force_slot or _meal_slot_for(cursor.time)        # lunch/dinner/None
    if not slot_name or _meal_already_placed(slots, slot_name):
        return seq
    pick = _nearest_open_dining(dining, cursor.place, cursor.time, slot_name)  # 动线就近 + 营业中
    if not pick:                                                 # 无候选 → 留白（validate 不报错，DD-11 会给 fallback）
        return seq
    dur = MEAL_DURATION[slot_name]
    meal = {"seq": seq, "start_at": cursor.time, "end_at": cursor.time + timedelta(minutes=dur),
            "kind": "meal", "ref_table": "dining_picks", "ref_id": pick["id"],
            "title": f'{slot_name} · {pick["name"]}', "evidence": pick["evidence"],
            "_place": pick["location"], "_cost_cent": _dining_cost(pick)}
    slots.append(meal)
    cursor.time = meal["end_at"]; cursor.place = pick["location"]
    return seq + 1

def _append_return_buffer(slots, cursor, ret_anchor, routes, seq):
    """末尾返程：动线接驳到发站 + 进站/值机缓冲，保证不误车。"""
    leg = _find_leg(cursor.place, _anchor_place(ret_anchor), routes)
    trans = _transit_slot(seq, leg, cursor.time); slots.append(trans); seq += 1
    buf_start = trans["end_at"]
    slots.append({"seq": seq, "start_at": buf_start,
                  "end_at": buf_start + timedelta(minutes=STATION_ARRIVAL_BUFFER_MIN),
                  "kind": "buffer", "ref_table": None, "ref_id": None,
                  "title": "进站/值机缓冲",
                  "evidence": {"source_type": "rule", "verification_status": "estimated",
                               "note": "返程进站缓冲（估算）"}})
    return seq + 1
```

> **锚点不可动**：`_collect_booking_anchors` 只读 `bookings WHERE confirmed=True`（DD-10 铁律），其 `start_at/end_at` 是排程的**硬边界**——活动排在到达之后、返程之前，`buffer` 保证赶得上返程。重规划时（§5.4）锚点原样保留。

### 5.2 硬约束校验 `validate`（v1 §9.5 落地）

```python
# dd12/validator.py
HARD_ISSUES = {"HARD_CONFLICT", "CLOSED", "RETURN_TIGHT", "OVER_BUDGET"}
RETURN_BUFFER_MIN = 90          # 到发站后至少留 90min（含进站+冗余；铁路默认，航空取 120，见 §9）

def validate(slots, constraints, attempts=1):
    issues, details = [], {}

    # ① 时段重叠 → HARD_CONFLICT（硬冲突率分子）
    ov = _find_overlaps(slots)
    if ov:
        issues.append("HARD_CONFLICT"); details["HARD_CONFLICT"] = ov

    # ② 返程缓冲不足 → RETURN_TIGHT（→ 条件边 retransport）
    tight = _check_return_buffer(slots, _return_buffer_min(slots))
    if tight:
        issues.append("RETURN_TIGHT"); details["RETURN_TIGHT"] = tight

    # ③ 违反营业/展期时间 → CLOSED
    closed = _check_open_hours(slots)
    if closed:
        issues.append("CLOSED"); details["CLOSED"] = closed

    # ④ 超预算 → OVER_BUDGET
    over = _check_budget(slots, constraints.get("budget_band"))
    if over:
        issues.append("OVER_BUDGET"); details["OVER_BUDGET"] = over

    hard = [i for i in issues if i in HARD_ISSUES]
    validation = {
        "ok": not hard,
        "issues": issues,
        "details": details,
        "metrics": {"hard_conflict": "HARD_CONFLICT" in issues,
                    "slot_count": len(slots), "attempts": attempts},
    }
    _emit_kpi(validation)          # DD-02 §12：硬冲突率埋点
    return validation

def _find_overlaps(slots):
    """相邻可占用时段（activity/meal/transport）两两检测 start<prev_end。lodging 可并行不计。"""
    occ = sorted([s for s in slots if s["kind"] in ("activity", "meal", "transport")],
                 key=lambda s: s["start_at"])
    bad = []
    for a, b in zip(occ, occ[1:]):
        if b["start_at"] < a["end_at"]:
            bad.append({"seq_a": a["seq"], "seq_b": b["seq"],
                        "overlap_min": int((a["end_at"] - b["start_at"]).total_seconds() // 60)})
    return bad

def _check_return_buffer(slots, need_min):
    """末活动/接驳结束到返程 transport 锚点开车之间，缓冲是否 ≥ need_min。"""
    ret = _return_transport_slot(slots)
    if not ret:
        return None
    last_active_end = max((s["end_at"] for s in slots
                           if s["kind"] in ("activity", "meal") and s["end_at"] <= ret["start_at"]),
                          default=None)
    if last_active_end is None:
        return None
    have = int((ret["start_at"] - last_active_end).total_seconds() // 60)
    return None if have >= need_min else {"return_seq": ret["seq"], "need_min": need_min, "have_min": have}

def _check_open_hours(slots):
    """activity/meal 槽位的 [start,end] 必须落在其来源实体的营业/展期窗口内。"""
    bad = []
    for s in slots:
        if s["kind"] in ("activity", "meal"):
            win = _source_open_window(s)     # 从 ref 实体读 open_hours / start_at~end_at
            if win and not (win[0] <= s["start_at"] and s["end_at"] <= win[1]):
                bad.append({"seq": s["seq"], "title": s["title"]})
    return bad or None

def _check_budget(slots, band):
    """累计 _cost_cent 与 constraints.budget_band 上限比较（单位分；band 单位元→×100）。"""
    if not band:
        return None
    total = sum(s.get("_cost_cent", 0) for s in slots)
    cap = band["max"] * 100
    return {"total_cent": total, "cap_cent": cap} if total > cap else None
```

**与 DD-02 条件边对齐**（`route_after_validate`，DD-02 §4）：

```python
# DD-02 已实现（本模块只保证 validation 结构契合）：
#   v["ok"] == True                         → "ok"        → compose
#   "RETURN_TIGHT" in v["issues"]           → "retransport"→ transport（重挑交通/返程班次）
#   其它硬冲突(HARD_CONFLICT/CLOSED/OVER_BUDGET) → "reflow" → timeline（重排）
```

> **硬冲突率 KPI**：`_emit_kpi` 把 `metrics.hard_conflict` 记入埋点（DD-02 §12 OTel span）。线上聚合 `sum(hard_conflict) / count(plans)` = **日程硬冲突率**（PRD 可信度指标），**出稿版目标恒为 0**（reflow 收敛后 compose 前必为 ok）。

### 5.3 天气动作 `compute_weather_actions`（v1 §9.6 落地）

```python
# dd12/weather.py
PRECIP_TH = 0.60                         # 降水概率阈值（§9 可配）
HEAT_TH   = 35.0                         # 高温阈值 ℃
ALERT_SET = ("暴雨", "强对流", "高温红色", "台风", "雷电")   # 命中即去高风险户外

def compute_weather_actions(slots, forecast):
    """对室外槽位逐一按阈值产出动作；天气不可用(forecast.ok=False)→空动作(降级跳过)。"""
    if not forecast.ok:
        return []
    actions = []
    for s in [x for x in slots if x.get("_outdoor") and x["kind"] == "activity"]:
        wx = forecast.at(s["start_at"], s.get("_place"))
        if wx is None:
            continue                                     # 该时段无天气数据 → 中性不动
        if wx.precip_prob >= PRECIP_TH:
            actions.append({"type": "demote_outdoor", "seq": s["seq"],
                            "add_indoor_alt": True, "reason": f"降水概率 {wx.precip_prob:.0%}",
                            "evidence": wx.evidence})
        if wx.temp >= HEAT_TH:
            actions.append({"type": "reduce_walking", "seq": s["seq"],
                            "reason": f"高温 {wx.temp:.0f}℃", "evidence": wx.evidence})
        if wx.alert and any(k in wx.alert for k in ALERT_SET):
            actions.append({"type": "drop_high_risk_outdoor", "seq": s["seq"],
                            "reason": wx.alert, "evidence": wx.evidence})
    return actions

def _apply_weather(acts, weather_actions):
    """把天气动作作用于活动候选集（在 solve_timeline 排点前）：
       - demote_outdoor：室外活动优先级下调，若存在室内备选则替换/补入；
       - reduce_walking：标记，接驳偏好 transit/taxi 而非步行（供 _find_leg 选段）；
       - drop_high_risk_outdoor：从候选集剔除该室外活动，改排室内备选。"""
    if not weather_actions:
        return acts
    by_seq = {a.get("seq"): a for a in weather_actions}
    out = []
    for a in acts:
        act = dict(a)
        wa = _match_action(act, by_seq)                  # 按 activity_id/seq 关联动作
        if wa and wa["type"] == "drop_high_risk_outdoor":
            alt = _indoor_alternative(act)               # 同主题室内备选（DD-08 候选池）
            if alt:
                out.append(alt)
            continue                                     # 高风险户外剔除
        if wa and wa["type"] == "demote_outdoor":
            act["_priority"] = act.get("_priority", 0.5) * 0.5   # 降权
            alt = _indoor_alternative(act)
            if alt:
                out.append(alt)
        if wa and wa["type"] == "reduce_walking":
            act["_prefer_mode"] = "transit"              # _find_leg 据此避免长步行
        out.append(act)
    return out
```

**天气动作语义（对齐 PRD §5.9）**：

| 条件 | 动作 | 排程效果 |
|---|---|---|
| 降水概率 ≥ 0.6 | `demote_outdoor`（+室内备选） | 室外活动优先级 ×0.5，补入同主题室内备选 |
| 气温 ≥ 35℃ | `reduce_walking` | 该活动接驳偏好 transit/taxi，减少长距离步行 |
| 预警命中 `ALERT_SET` | `drop_high_risk_outdoor` | 从候选集剔除高风险户外，改排室内备选 |

### 5.4 重入逻辑（经 DD-02 `trigger_replan` 从 timeline/dining 重入）

天气重规划**不是独立节点**，而是由 DD-13 天气检查（72h/24h/手动）计算动作后，经 DD-02 §8 `trigger_replan(plan_id, "weather", from_node)` 从 `timeline` 或 `dining` 重入，只重算受影响子图。本模块提供重入时 `timeline` 节点的**天气分支**：

```python
# dd12/node.py —— timeline 节点实现（含天气重规划分支）
async def timeline_solver(state: TripPlanState) -> dict:
    reason = state.get("replan_reason")
    weather_actions = None
    warnings = []

    if reason == "weather":
        # 天气重入：取当前时间线覆盖时段的预报，算动作（已确认 bookings 不动）
        weekend = {"start": state["constraints"]["earliest_depart"],
                   "end":   state["constraints"]["latest_return"]}
        forecast = await fetch_forecast(state.get("timeline", []), weekend)  # DD-04，禁裸调
        if not forecast.ok:
            warnings.append("天气数据不可用，跳过天气重规划，保留原时间线")   # §8 降级
        else:
            weather_actions = compute_weather_actions(state["timeline"], forecast)
            if not weather_actions:
                warnings.append("当前天气无需重规划（未触发阈值）")

    slots = solve_timeline(
        bookings=state["bookings"],            # confirmed 锚点，恒定
        activities=state["activities"],        # DD-08 选定（天气动作在 solve 内作用）
        dining=state.get("dining", []),        # DD-11 饭点
        local_routes=state.get("local_routes", []),  # DD-11 接驳
        weather_actions=weather_actions,
    )
    await persist_slots(state["plan_id"], slots)   # 写 timeline_slots（DD-01 §8.5）
    return {"timeline": slots, "warnings": warnings}
```

**"只重算受影响子图"的保证**：
1. **入口即 `timeline`**：`trigger_replan(from_node="timeline")` → LangGraph 从 `timeline` 续跑 `timeline → validate → compose`，**不重算** `parse~transport~hotel~mobility`（DD-02 §9 checkpoint 保证）。
2. **降水/预警影响餐饮**（如原室外午餐点需改室内）时，`from_node="dining"` → 重入 `dining → timeline → validate → compose`，DD-11 重挑饭点后再排。
3. **交通锚点恒定**：`solve_timeline` 只调整活动/餐饮/接驳，`bookings` 锚点 `start_at/end_at` 原样保留 → 已确认车次/航班/酒店在时间线上位置不变。
4. **稳定重排**：未受天气动作影响的活动按相同 `_order_by_open_and_priority` 排序，slot 位置稳定，仅受影响 slot 变化（对齐 DD-02 §13"仅受影响槽位变化"）。

## 7. 证据与状态（槽位透传各来源 evidence）

**铁律**：`timeline_slots.evidence` **一律透传来源实体的 evidence，本模块不新造、不升级、不降级**（DD-03 §8"透传，不新造"）。唯一例外：系统估算的 `buffer`/`free` 与直线估兜底接驳，标 `rule → estimated`。

| 槽位 kind | ref_table | evidence 来源 | verification_status |
|---|---|---|---|
| `transport`（交通锚点） | `bookings` | 透传 DD-10 锚点 | `confirmed_by_user`（用户确认） |
| `transport`（市内接驳） | `route_legs` | 透传 DD-11 路段 | amap→`public_source_observed` / rule→`estimated` |
| `activity` | `activities` | 透传 DD-08 活动 | `official_source_confirmed` / `public_source_observed`（原样） |
| `meal` | `dining_picks` | 透传 DD-11 饭点 | amap→`public_source_observed` |
| `lodging`（入住/离店） | `bookings` | 透传 DD-10 酒店锚点 | `confirmed_by_user` |
| `buffer`（返程/进站缓冲） | `NULL` | 系统估算 | `rule → estimated`（标"估算"） |
| `free`（空闲/机动） | `NULL` | 系统估算 | `rule → estimated` |

> **天气动作证据**：`compute_weather_actions` 产出的每个 action 带 `wx.evidence`（`qweather → public_source_observed`）。天气导致的槽位变化（如换室内活动）在 bundle 里由 DD-13 标注"因天气调整"，动作证据供前端展示决策依据；被替换进的室内活动仍透传其自身 `activities.evidence`。

## 8. 降级策略

| 触发 | 降级路径 | 用户体验/标注 |
|---|---|---|
| **校验不过（HARD_CONFLICT/CLOSED/OVER_BUDGET）** | 条件边 `reflow` → `timeline` 重排：`_relax_and_resolve`（丢弃最低优先级活动 / 压缩机动 `free` / 缩短活动时长到下限） | 收敛为无硬冲突；`warnings` 记录"已自动调整" |
| **返程太赶（RETURN_TIGHT）** | 条件边 `retransport` → `transport`（DD-09 重挑更晚返程班次或提示改签） | 保证赶得上；提示"返程偏紧，建议改晚班次" |
| **回退超 N 次仍不过**（`attempts > MAX_REFLOW`） | 熔断：产出**带风险提示的次优方案**（保留冲突但标注），不死循环（DD-02 §10） | 时间线标红冲突段 + "此段偏紧，请酌情调整" |
| **天气 Provider 不可用**（`forecast.ok=False`） | 跳过天气重规划，保留原时间线 | `warnings`："天气数据暂不可用，未做天气调整" |
| **无匹配 route_leg** | `_find_leg` 规则直线估兜底（`rule→estimated`） | 接驳标"估算耗时"，提示以地图为准 |
| **无饭点候选** | 留白，不插餐（DD-11 保证 `is_fallback` 稳妥备选，下次重挑） | 时间线不报错；餐段显示"待补充" |
| **无交通锚点**（同城/未回填） | 从周末窗口起点排点，末尾不加返程锚点 | 探索期/同城可用；确认版待回填后重算 |

```python
# dd12/relax.py —— reflow 时的松弛重排（确定性、可解释）
MAX_REFLOW = 3

def relax_and_resolve(state, validation):
    """按 issue 类型施加最小松弛，返回调整后的 activities/参数供 timeline 重排。"""
    acts = list(state["activities"])
    if "HARD_CONFLICT" in validation["issues"] or "OVER_BUDGET" in validation["issues"]:
        acts = _drop_lowest_priority(acts)          # 丢弃 1 个最低优先级（或最贵）活动
    if "CLOSED" in validation["issues"]:
        acts = _reschedule_or_drop_closed(acts, validation["details"]["CLOSED"])
    return acts
```

```yaml
  alert_keywords: ["暴雨","强对流","高温红色","台风","雷电"]
reflow:
  max_attempts: 3                  # 回退熔断次数（超出产次优方案）
```

- **返程缓冲按交通类型取值**：`_return_buffer_min(slots)` 检测返程锚点 `subtype`（train→`return_buffer_rail_min`，flight→`return_buffer_air_min`）。
- **天气配额**：`fetch_forecast` 经 DD-04 `ResilientProvider`，天气缓存 1h（DD-04 §4.1），72h/24h 检查命中缓存不重复外呼；接近日配额自动降级 `unknown`（→跳过重规划）。
- **权重与阈值热加载**：Pydantic `TimelineConfig` 加载，运营可按季节调 `precip_prob_threshold`（如梅雨季调低）。

## 10. 效果与验收标准（DoD）

### 10.1 验收指标

| 指标 | 目标 | 度量 |
|---|---|---|

## 11. 开发任务拆解

1. `timeline_slots` repo（`persist_slots`/查询）+ Slot 字典 ↔ 表列映射（0.5d）
2. 上游锚点/路段/饭点/活动的读取适配（`_collect_booking_anchors`/`_index_routes`/`_select_activities`）（0.5d）
3. 贪心排点 `solve_timeline` + 子过程（接驳/插餐/返程缓冲）（1.5d）
4. 硬约束校验 `validate`（overlaps/return_buffer/open_hours/budget）+ 条件边契合（1d）
5. 硬冲突率 KPI 埋点 `_emit_kpi`（配合 DD-02 §12）（0.5d）
6. `timeline`/`validate` 节点封装 + 挂 DD-02 图（0.5d）
7. 天气：`fetch_forecast`（接 DD-04）+ `compute_weather_actions` + `_apply_weather`（1d）
8. 重入逻辑（天气分支 + `trigger_replan` 对接 DD-13 触发点）（1d）
9. reflow 松弛重排 `relax_and_resolve` + 熔断（0.5d）
10. 降级路径（天气不可用/无路段/无饭点/无锚点）（0.5d）
11. 验收用例（贪心/校验/天气/重入/证据透传）+ 硬冲突率回归（1.5d）

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| **贪心非全局最优**（活动顺序次优） | 周末规模小（≤8 活动），开放时间+优先级贪心足够；可解释、可回退；`reflow` 松弛兜底；如需再引入局部交换启发式（不引重型求解器） |
| **route_legs 缺段导致接驳失真** | 直线估兜底（`rule→estimated` 标注）；DD-11 优先补齐动线关键段；估算态前端明示 |
| **返程缓冲拍脑袋**（误车风险） | 按交通类型配置（铁路 90/航空 120）；`RETURN_TIGHT` 硬校验 + retransport 回退；进站缓冲独立槽可视 |
| **天气误触发/漏触发** | 阈值配置化 + 参数化测试对齐 §5.3；预警关键词白名单；降级 `ok=False` 时保守跳过 |
| **重规划改动过大**（用户困惑） | 稳定重排（未受影响 slot 不动）+ 锚点恒定 + diff 断言；DD-13 标注"因天气调整"仅受影响段 |
| **reflow 死循环** | `MAX_REFLOW=3` 熔断 → 次优方案带风险提示（DD-02 §10） |
| **证据被误升级/新造** | 透传铁律 + CI SQL 断言（`timeline_slots.evidence` == 来源实体）；`buffer/free` 恒 `estimated` |
| **硬冲突率非 0 漏网** | compose 前 `validate` 必 `ok` 才走 compose（条件边保证）；埋点线上监控，非 0 报警 |
