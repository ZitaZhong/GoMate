# DD-05/DD-06/DD-17 市内活动场景增补

**详细设计增补 · 市内活动检索 + 情报源 + 深研扩展 · v1.0 · 2026 年 7 月**

> 本文为 DD-05（检索服务）、DD-06（活动情报流水线）、DD-17（实时深度研究）的市内活动场景增补。GoMate 新增市内多人活动模式后，这三个模块需要扩展以同时支持**跨城**和**市内**两种活动检索/研究场景。核心原则："**当周即研**"不区分跨城与市内——上海本周末的展览同样需要 DD-17 实时深研 + DD-03 证据六态定级。

### 1.2 市内检索策略

市内模式的检索与跨城模式的差异：

| 维度 | 跨城模式 | 市内模式 |
|------|---------|---------|
| 空间范围 | 全国 15-20 城 | 单城市内 radius_km 范围 |
| 时间匹配 | 整个周末（周五晚~周日） | 半日时间窗（如 14:00-21:00） |
| 主题匹配 | 活动类型 + 兴趣 | GoMate 主题分类（6大类30+子类）精准匹配 |
| 排序因子 | 活动价值 + 可达性 | 通勤公平性 + 兴趣匹配 + 时间匹配 |
| 深研触发 | 每次强制全量 | **同样每次强制全量** |

### 1.3 主题→查询映射

GoMate 主题分类到检索 query 的映射（示例）：

```python
THEME_QUERY_MAP: dict[str, list[str]] = {
    "看展": ["展览", "美术馆", "博物馆", "画展", "摄影展"],
    "博物馆": ["博物馆", "特展", "常设展"],
    "看话剧": ["话剧", "戏剧", "舞台剧", "音乐剧"],
    "Livehouse": ["livehouse", "现场音乐", "乐队演出"],
    "音乐会": ["音乐会", "交响乐", "演奏会"],
    "逛书店": ["书店", "独立书店", "阅读空间"],
    "逛公园": ["公园", "绿地", "户外"],
    "Citywalk": ["citywalk", "城市漫步", "街区", "历史建筑"],
    "市集": ["市集", "集市", "手作市集", "创意市集"],
    "陶艺": ["陶艺", "陶瓷体验", "手工陶"],
    "Brunch": ["brunch", "早午餐", "周末早午餐"],
    "咖啡馆": ["咖啡", "精品咖啡", "咖啡馆"],
    "桌游": ["桌游", "桌游吧", "德式桌游"],
    "密室": ["密室逃脱", "密室", "沉浸式"],
    "攀岩": ["攀岩", "抱石", "攀岩馆"],
}

def theme_to_queries(theme: str, city: str, date: str) -> list[str]:
    """将 GoMate 主题转换为 DD-17/DD-05 使用的检索 query。"""
    keywords = THEME_QUERY_MAP.get(theme, [theme])
    queries = []
    for kw in keywords:
        queries.append(f"{city} {date} {kw}")
        queries.append(f"{city} 本周末 {kw}")  # 自然语言变体
    return queries
```

## 3. DD-17 实时深度研究增补

### 3.1 市内深研 Query 模板

DD-17 深研的有界迭代策略同样适用于市内场景。市内深研的 query 生成：

```python
def build_local_research_queries(
    theme: str,
    city: str,
    date: str,
    time_window: dict | None = None,
    constraints: dict | None = None,
) -> list[str]:
    """为市内活动生成深研搜索 query。

    策略：多源 + 官方核实（与跨城一致）。
    特点：① 强调"本周末"时效性；② 加入场馆/区域限定；③ 预约/售票状态查询。
    """
    base_queries = theme_to_queries(theme, city, date)
    # 追加官方核实 query
    verify_queries = [
        f"{city} {theme} 官方 预约",
        f"{city} {theme} 门票 开放时间",
    ]
    # 约束相关 query
    constraint_queries = []
    if constraints:
        if constraints.get("indoor_only"):
            constraint_queries.append(f"{city} 室内 {theme}")
        if constraints.get("budget_max"):
            constraint_queries.append(f"{city} 免费 {theme}")
    return base_queries + verify_queries + constraint_queries
```

### 3.3 市内深研流程（与跨城对比）

| 步骤 | 跨城深研 | 市内深研 |
|------|---------|---------|
| 1. 搜索 | "北京 本周末 展览" | "上海 本周末 看展" |
| 2. 多源聚合 | 各城活动页 | 文旅局/场馆官网/搜索 |
| 3. 官方核实 | 回官方源确认时间/票况 | **同样回官方核实**（场馆页/文旅局） |
| 4. 抽取定级 | DD-03 六态 | **同样六态**（official_source_confirmed 等） |
| 5. 入库 | `ingest_realtime(scope="cross_city")` | `ingest_realtime(scope="local")` |
| 6. 触发方式 | 每次强制全量 | **同样每次强制全量** |
| 7. 超时处理 | partial 返回 + 继续异步 | **同样 partial** |
| 8. 证据链 | source_url + fetched_at + status | **完全一致** |

## 4. 跨城与市内的统一检索入口

### 4.1 模式判定逻辑

DD-15 Copilot 在意图分类时增加 `scope` 判定：

```python
# DD-15 意图分类扩展
class IntentClassification(TypedDict):
    intent: str           # provide_constraints / deep_research / ...
    scope: str            # "cross_city" | "local" | "ambiguous"
    # scope 判定规则：
    # - 提到其他城市名 → cross_city
    # - 提到"上海"/"市内"/"附近" + 活动类型 → local
    # - 创建了 Room → local
    # - 模糊不清 → 追问确认
```

### 4.2 检索结果融合

无论 scope 是什么，检索结果最终都经过：
1. DD-03 证据定级（六态不变）
2. DD-05 `retrieve_activities` 统一接口
3. DD-17 深研（如启用）
4. 个性化重排（DD-05 rerank，复用兴趣偏好）

**唯一区别**：市内模式额外计算**通勤公平性**（DD-18 §4.3），跨城模式额外计算**门到门耗时**（DD-09）。

## 5. 验收标准

| 项 | 标准 |
|---|---|
| 市内检索 | `retrieve_activities(scope="local", city="上海", theme="看展")` 返回带证据的活动列表 |
| 深研覆盖 | 市内活动同走 DD-17 深研，返回结果带 `evidence.source_url` |
| 官方核实 | 场馆官网来源活动标记为 `official_source_confirmed` |
| 时间窗过滤 | 只返回在 `time_window` 内开放的活动 |
| 预约状态 | 已约满活动不进入主推荐，可作为"类似活动参考" |
| 种子数据兜底 | DD-17 超时或无结果时，返回 MVP 种子数据（标注 estimated） |
| 入库一致 | 市内/跨城活动走同一 `activities` 表，`city_code` 区分 |

---

> 本文为 DD-05/DD-06/DD-17 的增补，不改变原有跨城逻辑。新增 `scope` 参数使同一接口同时服务两种模式。证据体系（DD-03）和深研策略（DD-17 有界迭代）完全复用，只是 query 模板和来源注册表扩展了市内场景。
