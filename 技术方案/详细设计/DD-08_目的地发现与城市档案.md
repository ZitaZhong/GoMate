# DD-08 目的地发现与城市档案 · 详细设计

**详细设计系列 · 领域节点文档 · v1.0 · 2026 年 7 月**

> 本文定义「周末去哪儿」的**核心差异化模块**：`discover`（目的地发现）与 `research`（活动研究）两个 LangGraph 节点，以及它们赖以工作的运营资产 **City Playbook（城市档案）+ venues（场馆目录）**。
>
> 产品差异化的落点在这里——**目的地由"当周活动"驱动**（DD-05 检索到的、带 evidence 的真实当周活动），而不是竞品那种"热门景点排列组合"。城市不是"哪里好玩"，而是"**本周末这里有什么值得专程去的事**"。
>
> **上游依据**：v1 §5.2（节点流水线 [2]DestinationDiscovery/[3]ActivityResearch、§9.2 门到门 door_to_door）、doc2/PRD §5.2（城市评分公式）、PRD §6.1（城市方向卡形态）、v1.1 增补 A（活动检索）、增补 E②③（并行扇出 + 屏障 + 真连边）。
> **契约依赖**：DD-01（`city_playbook`/`venues`/`activities` 表、evidence JSONB、归属矩阵）、DD-02（`discover`/`research` 节点契约、`TripPlanState`、并行 + 屏障）、DD-03（城市卡字段定级、活动透传）、DD-04（地图门到门粗估、天气；禁裸调）、DD-05（`retrieve_activities`）。
> **下游消费者**：DD-02（作为节点挂图）、DD-09 交通策略（消费选定城 + 门到门粗估）、DD-13（渲染城市卡）、BFF/前端（SSE `node_output`）。
> **一句话**：**当周活动价值 × 可达性 × 有效游玩 × 预算 × 天气 × 餐饮 − 风险 − 门到门惩罚，并行给多个候选城市打分，输出 3 张带 evidence 的城市方向卡。**

**设计原则**：① **活动驱动**——城市排序的第一权重来自当周活动价值（DD-05 检索结果），不是静态热门度；② **探索期粗估控成本**——`discover` 用直线/距离矩阵/城市中心做门到门**粗估**，精算留给 DD-09；③ **证据一等公民**——城市卡每个对外字段带 evidence，理由/预算/耗时按 DD-03 定级；④ **只读活动库**——遵守 DD-01 归属矩阵与 DD-02 读写解耦铁律。

## 2. 设计目标与非目标

**目标**：
1. **非同质**：候选城市由"当周有什么活动"驱动，同一出发地、不同周末应给出**明显不同**的候选城与理由（正面回应竞品"排列组合"）。
2. **可解释**：每张城市卡都能回答"**为什么本周值得去**"，且理由挂在具体活动/证据上，不空泛。
3. **低成本探索**：`discover` 阶段只用粗估（直线距离/距离矩阵/城市中心坐标），不触发精算与实时抓取；成本随候选城数线性可控。
4. **可配置**：评分权重、候选城池、粗估阈值全部走配置，运营可调，不改代码。
5. **可并行**：多候选城打分并行扇出，屏障合并，显著降低探索版延迟（DD-02 §9 BSP）。

**非目标**：
- ❌ 不做门到门**精算**与交通策略卡（DD-09）；`discover` 只出"推荐交通"的粗判断。
- ❌ 不写 `activities`（DD-06 专属）；不新造活动事实（DD-05 透传 evidence）。
- ❌ 本模块不自己抓取（交 DD-17/DD-06）；v2 起 `research` **每轮强制调 DD-17 实时深研**（有界迭代→实时入库），DD-05 检索作库垫场并融合；DD-06 异步补搜降为兜底。
- ❌ 不做交易/比价。

### 4.2 城市卡 DTO：`CityCandidate`（写入 `state.candidate_cities`，SSE `node_output` 载荷）

```python
from dd03 import Fact   # DD-03 Fact[T] = {value, evidence}

class TransportHint(BaseModel):
    mode: str                      # "rail" | "air" | "mixed"
    summary: str                   # "周五晚飞机 / 周六早高铁"（粗判，精算在 DD-09）
    est_door_to_door_min: int      # 门到门粗估总分钟（单程，最优候选）

class ActivityHighlight(BaseModel):
    activity_id: int
    title: str
    venue: str | None
    verification_status: str       # 透传自 activities.evidence（不新造）
    rerank_score: float            # 来自 DD-05

class CityCandidate(BaseModel):
    city_code: str
    name: str
    theme: str                     # 方向主题，如 "展览与城市文化"（由 weekend_tags∩interests 生成）

    # —— 城市方向卡对外字段（PRD §6.1），每个都是 Fact（带 evidence，前端据 status 渲染六态）——
    why_this_week: list[Fact[str]] # "本周推荐理由"：每条挂在具体活动/证据上
    recommended_transport: Fact[TransportHint]   # evidence: rule/amap → estimated
    budget_estimate: Fact[dict]    # {"min":2100,"max":2900,"currency":"CNY","per":"person"} → estimated
    effective_play: Fact[dict]     # {"min_h":18,"max_h":22} 有效游玩时间 → estimated
    risks: list[Fact[str]]         # "主要风险"：延误/售罄/夜间返程紧张…
    to_confirm: list[str]          # "待确认清单"：核心活动需官方确认、余票以官方为准…

    # —— 排序与解释（内部 + 可观测）——
    score: float                   # 综合分（§5 公式）
    score_breakdown: dict          # 各子分 + 惩罚项，供调试/埋点
    driven_by_activities: list[ActivityHighlight]  # 驱动本城入选的核心活动（透传 evidence）
```

## 5. 核心算法

### 5.1 评分公式（PRD §5.2 落地，加权和 + 惩罚项）

PRD §5.2 的自然语言公式：

```text
当周活动价值 + 交通可达性 + 有效游玩时间 + 总预算适配 + 酒店和市内交通便利 + 天气适配 + 餐饮吸引力
  − 延误和售罄风险 − 门到门时间惩罚
```

工程化为**归一化子分（各 ∈ [0,1]）的加权和，减去惩罚项**（权重可配置，§9）。**活动价值权重最高**——这是"活动驱动"的算法保证：

```python
def score_city(inp: CityScoreInput) -> tuple[float, dict]:
    w = inp.weights
    c = inp.constraints

    # ① 当周活动价值 S_act（核心差异化，权重最高）
    #   = 官方确认核心活动数 + top-N rerank 分聚合 + 与 interests 主题契合
    S_act = activity_value_score(inp.activity_candidates, c.get("interests", []))

    # ② 交通可达性 S_reach：门到门粗估总耗时越短越高（sigmoid 归一）
    S_reach = reachability_score(inp.door_to_door["total_min"])

    # ③ 有效游玩时间 S_play：门到门后剩余可玩时长 / 周末理论窗口
    S_play = effective_play_score(inp.weekend, inp.door_to_door["total_min"])

    # ④ 总预算适配 S_budget：粗估人均预算落在 budget_band 内→高，越界越低
    est_budget = estimate_budget(inp.door_to_door, inp.city, inp.activity_candidates)
    S_budget = budget_fit_score(est_budget, c.get("budget_band"))

    # ⑤ 酒店+市内交通便利 S_local：住宿区密度 + 夜间交通风险（来自 city_playbook）
    S_local = local_convenience_score(inp.city)

    # ⑥ 天气适配 S_weather：降水概率/预警 + 室内活动占比对冲
    S_weather = weather_score(inp.weather, inp.activity_candidates, inp.city)

    # ⑦ 餐饮吸引力 S_dining：住宿区 dining_density + 城市美食标签
    S_dining = dining_score(inp.city)

    # —— 惩罚项 ——
    # 延误/售罄风险 P_risk：天气预警 + 季节风险 + 活动 sold_out/售罄 + 起售紧张
    P_risk = risk_penalty(inp.weather, inp.city, inp.activity_candidates)
    # 门到门时间惩罚 P_door：超过阈值（如单程 > 4h）线性惩罚
    P_door = door_penalty(inp.door_to_door["total_min"], w.door_penalty_threshold_min)

    score = (w.act * S_act + w.reach * S_reach + w.play * S_play +
             w.budget * S_budget + w.local * S_local +
             w.weather * S_weather + w.dining * S_dining
             - w.risk * P_risk - w.door * P_door)

    breakdown = {"S_act":S_act,"S_reach":S_reach,"S_play":S_play,"S_budget":S_budget,
                 "S_local":S_local,"S_weather":S_weather,"S_dining":S_dining,
                 "P_risk":P_risk,"P_door":P_door,"est_budget":est_budget}
    return score, breakdown
```

**关键子分实现**（真实可跑，其余同构）：

```python
import math

def activity_value_score(cands: list, interests: list[str]) -> float:
    """活动驱动的核心分：官方确认核心活动 + rerank 聚合 + 主题契合。"""
    if not cands:
        return 0.0
    OFFICIAL = ("official_source_confirmed", "confirmed_by_user")
    official_n = sum(1 for a in cands if a.verification_status in OFFICIAL)
    # 官方确认活动数：0→0, 3+→1（饱和），保证"有真活动"才高分
    f_official = min(official_n / 3.0, 1.0)
    # top-5 rerank 分均值（DD-05 已归一到相关性）
    top = sorted((a.rerank_score for a in cands), reverse=True)[:5]
    f_rerank = sum(top) / len(top) if top else 0.0
    # 主题契合：候选活动 category/tags 命中用户 interests 的比例
    hit = sum(1 for a in cands[:10] if _match_interests(a, interests))
    f_theme = min(hit / 5.0, 1.0)
    return 0.5 * f_official + 0.3 * f_rerank + 0.2 * f_theme   # 官方确认权重最高

def reachability_score(total_min: int) -> float:
    """门到门越短越高：sigmoid，90min→~0.9，240min→~0.5，360min→~0.2。"""
    return 1.0 / (1.0 + math.exp((total_min - 240) / 60.0))

def effective_play_score(weekend: dict, door_min: int) -> float:
    """有效游玩 = 周末理论窗口 - 2*门到门(往返)；除以窗口归一。"""
    window_h = _weekend_window_hours(weekend)          # 如两天一夜≈30h 可支配
    play_h = max(window_h - 2 * door_min / 60.0, 0.0)
    return min(play_h / max(window_h, 1e-6), 1.0)

def budget_fit_score(est: dict, band: dict | None) -> float:
    """粗估人均预算 vs 用户区间：区间内=1，超上限线性衰减，低于下限轻微降（性价比反而好→给 0.9）。"""
    if not band:
        return 0.6                                      # 无预算约束→中性
    lo, hi, mid = band["min"], band["max"], est["mid"]
    if lo <= mid <= hi:
        return 1.0
    if mid > hi:
        return max(1.0 - (mid - hi) / max(hi, 1), 0.0)
    return 0.9                                           # 低于下限：便宜，轻微降（怕体验缩水）

def weather_score(weather: dict, cands: list, city: dict) -> float:
    """降水概率高→降分，但室内活动占比高可对冲（呼应 PRD 室内体验适配）。"""
    precip = weather.get("precip_prob", 0.0)
    indoor_ratio = _indoor_ratio(cands)                 # 展览/演出/博物馆算室内
    base = 1.0 - precip                                 # 降水概率直接扣
    return base + (1.0 - base) * indoor_ratio * 0.7     # 室内活动多→天气影响被对冲

def door_penalty(total_min: int, threshold_min: int) -> float:
    """单程超阈值（默认 240min）线性惩罚，封顶 1.0。"""
    if total_min <= threshold_min:
        return 0.0
    return min((total_min - threshold_min) / 240.0, 1.0)
```

> 预算粗估 `estimate_budget` 用**规则**（往返交通粗价档 + 住宿区档位 + 活动票价原文均值），产出 `{"min","mid","max"}`，来源 `rule` → DD-03 定级 `estimated`（§7）。**绝不用 LLM 生成票价/预算精确值**。

### 5.2 并行扇出 + 屏障（DD-02 §9 BSP）

`discover` 对**候选城池**（constraints 圈定的 N 个城，见 §5.3）并行打分。每城的打分需要：门到门粗估（DD-04/DD-09）+ 活动检索（DD-05）+ 天气（DD-04）——都是**确定性计算/已就绪数据读取**，天然可并行（增补 E②：并行的不是实时抓取）。

```python
import asyncio

async def destination_discovery(state: TripPlanState) -> dict:
    c = state["constraints"]
    weekend = {"start": c["earliest_depart"], "end": c["latest_return"]}
    weights = load_weights()                                    # §9 配置
    pool = candidate_city_pool(c)                              # §5.3 候选城池（含降级）

    # —— 并行扇出：每城一个协程，内部并发拉三路输入再打分 ——
    async def score_one(city_code: str) -> CityCandidate | None:
        city = load_city_playbook(city_code)                  # 读 city_playbook（只读）
        origin = c["origins"][0]                              # 主出发地（多出发地取聚合）
        # 三路输入并发（各自经 DD-04 ResilientProvider，带缓存/降级）
        d2d, weather, acts = await asyncio.gather(
            estimate_door_to_door(origin, city, weekend),     # §6 DD-09 粗估 / DD-04 map 兜底
            fetch_weather(city, weekend),                     # §6 DD-04 qweather
            retrieve_city_activities(city_code, weekend, c),  # §6 DD-05 retrieve_activities(top_k=20)
        )
        if not feasible(d2d, weekend):                        # 门到门粗估已使周末不成立
            return None
        inp = CityScoreInput(constraints=c, city=city, activity_candidates=acts,
                             door_to_door=d2d, weather=weather, weekend=weekend, weights=weights)
        sc, bd = score_city(inp)
        return assemble_city_card(city, inp, sc, bd)          # §5.4 组装（Guard 定级）

    cards = [x for x in await asyncio.gather(*[score_one(cc) for cc in pool]) if x]

    # —— 屏障：本节点内已 gather 汇聚（单节点内并发，非 LangGraph 多节点扇出）——
    # 若改用 LangGraph Send 多节点扇出，则 candidate_cities 的 reducer(operator.add) 在屏障节点合并（DD-02 §9）
    cards.sort(key=lambda x: x.score, reverse=True)
    top3 = cards[:3]
    warnings = []
    if not top3:
        return degrade_no_feasible_city(c)                    # §8 跨城不成立 → 近郊/同城
    if len(top3) < 3:
        warnings.append("可行候选城不足 3 个，已返回全部可行方向")
    return {"candidate_cities": top3, "warnings": warnings}
```

> **实现选择**：v0.1 用**单节点内 `asyncio.gather` 并发**（候选城 5~8 个，粗估成本低，无需跨节点调度），规避 BSP 超步隐坑（DD-02 §15）。若候选城扩大或打分变重，再切 LangGraph `Send` 多节点扇出 + 屏障节点，`candidate_cities` 的 `operator.add` reducer 负责合并（DD-02 §3 铁律），行为等价。

### 5.3 候选城池 `candidate_city_pool`

```python
def candidate_city_pool(c: dict) -> list[str]:
    """从主出发地出发，圈定粗估可达的城市池（不做精算，仅直线距离 + 交通方式初筛）。"""
    origin = c["origins"][0]
    accept_flight = c.get("accept_flight", True)
    all_cities = list_enabled_city_playbooks()                # 15~20 城种子
    pool = []
    for city in all_cities:
        if city["city_code"] == origin_city_code(origin):
            continue                                          # 排除出发城本身（同城降级另走 §8）
        straight_km = haversine(origin_geo(origin), city["center"])
        # 铁路合理半径 ~800km（高铁 3~4h），航空扩到 ~2000km；不接受飞行则只留铁路半径
        max_km = 2000 if accept_flight else 800
        if straight_km <= max_km:
            pool.append(city["city_code"])
    return pool[:8]                                           # 上限 8，控成本（§9）
```

### 5.4 城市卡组装 `assemble_city_card`（证据定级在此发生）

```python
from dd03 import enforce_provenance   # 闸一：由 field + source_type 决定 status

def assemble_city_card(city, inp: CityScoreInput, score: float, bd: dict) -> CityCandidate:
    acts = inp.activity_candidates
    theme = derive_theme(city["weekend_tags"], inp.constraints.get("interests", []))

    # 推荐交通（粗判）：rule/amap → estimated

                         summary=summarize_transport(inp.door_to_door),
                         est_door_to_door_min=inp.door_to_door["total_min"])
    f_transport = enforce_provenance("city.recommended_transport", hint,
                                     source_type=inp.door_to_door["evidence"]["source_type"],  # amap/rule
                                     source_url=inp.door_to_door["evidence"].get("source_url"))

    # 预算/有效游玩：rule → estimated（禁编）
    f_budget = enforce_provenance("city.budget_estimate", bd["est_budget"], source_type="rule")
    f_play   = enforce_provenance("city.effective_play",
                                  {"min_h": floor_h(bd), "max_h": ceil_h(bd)}, source_type="rule")

    # "为什么本周值得去"：每条挂具体活动 → 透传该活动 evidence（不新造）
    why = [build_reason_fact(a) for a in top_reason_activities(acts, k=3)]

    # 风险 + 待确认（rule/城市档案 → estimated；核心活动需官方确认写入 to_confirm）
    risks = [enforce_provenance("city.risk", r, source_type="rule") for r in collect_risks(inp)]
    to_confirm = build_to_confirm(acts, inp)                  # "核心活动需官方确认""余票以官方为准"

    return CityCandidate(
        city_code=city["city_code"], name=city["name"], theme=theme,
        why_this_week=why, recommended_transport=f_transport,
        budget_estimate=f_budget, effective_play=f_play,
        risks=risks, to_confirm=to_confirm,
        score=score, score_breakdown=bd,
        driven_by_activities=[ActivityHighlight(
            activity_id=a.id, title=a.title, venue=a.venue,
            verification_status=a.verification_status, rerank_score=a.rerank_score
        ) for a in acts[:5]],
    )

def build_reason_fact(a) -> "Fact[str]":
    """理由文本挂在活动上，透传活动原 evidence（DD-03 §8：不新造，透传）。"""
```

## 7. 证据与状态（城市卡定级 + 活动透传）

对齐 DD-03 §8 接线表「DD-08：门到门=rule/amap→observed/estimated；活动亮点透传」。**铁律**：任何对外字段不得直接构造 `Evidence` 的 confirmed 状态，必须经 `enforce_provenance`（DD-03 闸一）由 `field + source_type` 决定。

| 城市卡字段 | 来源 | 定级（经 `enforce_provenance`/`map_status`） |
|---|---|---|
| `why_this_week[]`（理由） | 挂在具体活动上 | **透传该活动的 evidence**（官方活动→`official_source_confirmed`；公开源→`public_source_observed`），不新造 |
| `recommended_transport` | 门到门粗估 amap/rule | amap→`public_source_observed`；rule(直线估)→`estimated` |
| `budget_estimate` | 规则粗估 | `rule` → `estimated`（必须标"估算"，**禁编精确价**） |
| `effective_play` | 规则（窗口−门到门） | `rule` → `estimated` |
| `risks[]` | 城市档案/规则 | `rule` → `estimated` |
| `to_confirm[]` | 提示文案 | 非事实值，纯提示（如"核心活动需在官方页确认""余票以官方为准"） |
| `driven_by_activities[]` | DD-05 活动 | `verification_status` **原样透传** |

**核心活动必须官方确认**（`research` 强约束，呼应 DD-05 §5.4 硬过滤）：

```python
def enforce_core_activity_confirmed(a) -> None:
    """核心活动（进城市卡理由/驱动列表）必须 official_source_confirmed；
    非官方源可作候选但不得标为'核心/已确认'，UI 显示'公开来源·待确认'或降级。"""
    CORE_OK = ("official_source_confirmed", "confirmed_by_user")
    if a.is_core and a.verification_status not in CORE_OK:
        a.is_core = False
        a.evidence.note = "非官方确认，降为候选；待官方核实"
```

> DD-03 闸二/闸三对本模块的意义：城市卡不含 `train.*`/`flight.*` 字段（推荐交通只是**粗判文案**，不含票价/余票/车次），故不会触发禁编断言；真正的交通事实在 DD-09/回填。**预算/游玩耗时一律 `estimated`，绝不 confirmed。**

## 8. 降级策略

| 触发 | 降级行为 | 状态标注 |
|---|---|---|
| **跨城不成立**（候选池空 / 全部门到门粗估超阈值使周末不可行） | `degrade_no_feasible_city`：改推**近郊/同城**方向——从出发城 `city_playbook` 的 `hubs`/近郊城生成"同城深度/近郊一日"候选卡 | `warnings` 记录；卡片标"跨城偏紧，推荐近郊/同城" |
| **某候选城活动检索空**（DD-05 返回空） | 触发 **DD-06 异步补搜**（不阻塞）+ 本次返回**官方源清单**（该城 `source_registry` 的官方入口）+ 关键词建议 | 官方源清单条目 `unknown`；`warnings` 提示 |
| **门到门粗估 Provider 降级**（DD-04 amap 熔断/超配额） | 退化为**直线距离 + 平均速度**估算 | `source_type=rule` → `estimated`，`degraded=True` |
| **天气 Provider 不可用** | 天气子分取中性（0.6），风险惩罚不加天气项 | 天气字段 `unknown`；不影响其它子分 |
| **候选城不足 3** | 返回全部可行方向（1~2 张） | `warnings` 提示"可行候选不足 3" |

```python
def degrade_no_feasible_city(c: dict) -> dict:
    """跨城不成立 → 近郊/同城。用出发城 playbook 的 hubs + 近郊城生成候选。"""
    origin_city = load_city_playbook(origin_city_code(c["origins"][0]))
    near = build_local_candidates(origin_city)                # 同城深度/近郊，门到门极短
    for card in near:
        card.risks.append(Fact(value="跨城时间偏紧，已改推近郊/同城方向",
                               evidence=_rule_ev()))
    return {"candidate_cities": near[:3],
            "warnings": ["跨城不成立，降级为近郊/同城候选"]}
```

### 9.2 探索期粗估成本控制

- **粗估优先直线**：候选池初筛用 `haversine`（零外呼）；只对入池城调 amap `distance_matrix`（**一次批量**多目的地，非逐城 route），命中 DD-04 缓存（route 7d）。

- **精算延后**：门到门精算/时刻表比选只在下游 `transport`（DD-09）对**选定城**做，不在扇出阶段全量精算。

## 10. 效果与验收标准（DoD）

**效果指标**（对应产品差异化）：

| 指标 | 目标 | 说明 |
|---|---|---|
| **候选城采纳率** | 用户从 3 张卡选 1 深入的比例 > 60% | 卡片质量与相关性 |
| **活动驱动非同质** | 同出发地、相邻两周的候选城重合度 < 50% | 证明由"当周活动"而非静态热门驱动（反"排列组合"） |
| **官方来源占比** | 城市卡 `driven_by_activities` 中 `official_source_confirmed` 占比 > 70% | 呼应 PRD 可信度指标 + DD-03 |
| **粗估成本** | 单次 discover 外呼 ≤ 8 城、p95 < 3s（缓存命中） | §9 成本控制 |

**功能验收**：
1. **活动驱动**：mock 两个周末不同 `activities`，同 `constraints` → 候选城排序明显不同（非同质快照测试）。
2. **评分正确**：给定 `CityScoreInput` golden set，`score_city` 输出与手算一致；权重改动线性影响排序（参数化测试）。
3. **并行无丢**：8 城并行扇出，屏障后 `candidate_cities` 完整（对齐 DD-02 §13 并行无丢更新）。
4. **证据定级**：城市卡 `budget_estimate`/`effective_play` = `estimated`；`recommended_transport`=`estimated`/`observed`；理由透传活动 evidence（组件级断言）。
5. **核心活动官方确认**：构造非官方核心活动 → 被降为候选、不进"已确认"（对齐 DD-03 §11.2）。
6. **降级**：① 候选池空 → 近郊/同城候选；② 检索空 → 触发补搜 + 官方源清单；③ amap 熔断 → 直线估 `estimated`。

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| **city_playbook 覆盖不足**（种子城少 → 候选池小） | v0.1 先 15~20 城（上海优先，DD-01 §10.2）；运营持续扩充；不足 3 城时降级返回全部可行方向 |
| **活动库空/稀**（DD-06 未预热 → 活动驱动失效，退回静态） | `research` 检索空触发 DD-06 补搜 + 官方源清单降级；效果指标监控"活动驱动非同质度"，低于阈值报警 |
| **粗估失真**（直线估与真实门到门偏差大 → 排序错） | 粗估仅用于**初筛与排序**，选定城由 DD-09 精算校正；门到门阈值/半径可配置回归 |
| **并行 BSP 隐坑**（节点被调度两次/reducer 丢更新） | v0.1 单节点内 `asyncio.gather`（无跨节点扇出）；若切 `Send` 则显式屏障 + `operator.add` reducer（DD-02 §9/§15） |
| **权重拍脑袋**（子分权重不合理 → 推荐质量差） | 权重配置化 + golden set 回归 + 采纳率/非同质度线上监控，数据驱动调参 |
| **证据绕过**（直接构造 confirmed） | 强制经 `enforce_provenance`（DD-03 闸一）+ lint 静态扫描（DD-03 §13）+ code review |
