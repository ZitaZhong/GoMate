**详细设计系列 · 前端交付层重构 · v1.2 · 2026 年 7 月**

> 本文定义前端从当前单文件 HTML Demo 重构为**现代化 Next.js PWA**的完整方案：同时承载**跨城周末规划**（现有 Trip Bundle）与**市内多人活动规划**（GoMate 房间模式）两种交互模式，共用设计系统、统一 Copilot 入口。
>
> **上游依据**：GoMate PRD §5-§18（页面/视觉/动效/功能）；DD-13（前端渲染契约/FactField/SSE）；DD-15（对话 Copilot/SSE 事件）；DD-18（房间状态机/API）；竞品调研（飞猪/ChatGPT/Mindtrip/Wanderlog/Google AI Canvas）。

### 2.3 字体规范

- 正文：系统无衬线字体（-apple-system 等），最小 14px
- 标题：轻度手写风（仅装饰用，如 `font-handwrite`），**`next/font/local` 自托管 woff2**（Caveat / ZCOOL KuaiLe 存 `public/fonts/`，不依赖 Google Fonts——国内网络环境不可用，且避免 FOUT）；字体文件缺失时静默降级为系统字体，不阻塞渲染
- 时间/预算/路线数据：**不使用手写字体**，保持清晰可读
- 行间距：正文 1.6，卡片内 1.4

### 2.4 动效规范（GoMate PRD §13.5）

| 动效 | 时长 | 场景 |
|------|------|------|
| 卡片出现 | 200-300ms | 活动推荐/行程节点逐个出现 |
| 转盘旋转 | 2000-3000ms | 主题转盘（**显式偏差，见下**） |
| 便签落入 | 300-400ms | 成员提交后便签卡动画 |
| 路线绘制 | 500ms | AI 生成路线时 |
| 分享展开 | 400ms | 分享卡片生成时纸张展开 |
| 流式文字 | 逐字 30ms | AI 回复 |

> **对 PRD 的显式偏差**：PRD §13.5 规定"动效时长 200—500ms（AI 生成过程除外）"。转盘旋转取 2—3s 超出该区间——转盘是"结果揭晓"型动效，减速—停顿过程是体验核心，500ms 内无法建立期待感。此处按显式偏差处理，需产品确认；其余动效全部遵守 200—500ms。

## 3. 核心组件实现

### 3.1 FactField 六态渲染（升级版，supersede DD-13 徽标视觉）

> **与 DD-13 的关系**：DD-13 §「六态渲染」规定的语义映射（状态→文案→视觉处理）不变；徽标的具体形态（实心/描边徽章+emoji）由本节统一替代——全站六态渲染以本文为准。变更原因：① 色相文字在白底上对比度仅 1.6—2.4:1，远低于 WCAG AA 4.5:1，最关键的"估算/可能过期"警示反而最看不清；② emoji 跨平台渲染不一致。
>
> **对比度规则**：色相只用于圆点、浅底色（`/15` 透明度）和边框；**徽标文字一律深色**（`text-primary` / `text-secondary`），保证 ≥4.5:1。

```tsx
// components/evidence/FactField.tsx
import type { ReactNode } from "react";

export interface Evidence {
  verification_status: string;
  source_url?: string;
  fetched_at?: string;
  source_type?: string;
  note?: string;
}

export interface FieldData {
  value: unknown;
  evidence?: Evidence;
}

// 色相在圆点和浅底色上；文字深色保证对比度 ≥ 4.5:1
const STATUS_META: Record<string, { label: string; badgeCls: string; dotCls: string }> = {
  confirmed_by_user:         { label: "已确认",   badgeCls: "bg-evidence-confirmed/15 text-primary",            dotCls: "bg-evidence-confirmed" },
  official_source_confirmed: { label: "官方确认", badgeCls: "bg-evidence-official/15 text-primary",             dotCls: "bg-evidence-official" },
  public_source_observed:    { label: "公开可查", badgeCls: "bg-black/5 text-secondary",                        dotCls: "bg-evidence-observed" },
  estimated:                 { label: "估算",     badgeCls: "bg-evidence-estimated/25 text-primary",            dotCls: "bg-evidence-estimated" },
  unknown:                   { label: "待确认",   badgeCls: "border border-dashed border-secondary/40 text-secondary", dotCls: "bg-evidence-unknown" },
  expired:                   { label: "可能过期", badgeCls: "bg-evidence-expired/15 text-primary",              dotCls: "bg-evidence-expired" },
};

export function FactField({
  field,
  render,
  className = "",
}: {
  field: FieldData;
  render?: (v: unknown) => ReactNode;
  className?: string;
}) {
  // fail-safe：evidence 缺失或 value 为空一律按 unknown 渲染（硬 KPI：未确认误展为已确认 = 0）
  const st = field.evidence?.verification_status ?? "unknown";
  const meta = STATUS_META[st] ?? STATUS_META.unknown;
  const isUnknown = st === "unknown" || field.value == null;
  const sourceUrl = field.evidence?.source_url;

  const badge = (
    <span className={`inline-flex items-center gap-1 px-1.5 py-0.5 rounded-badge text-xs ${meta.badgeCls}`}>
      <span className={`w-1.5 h-1.5 rounded-full ${meta.dotCls}`} />
      {meta.label}
    </span>
  );

  return (
    <span className={`inline-flex items-center gap-1.5 flex-wrap ${className}`}>
      {isUnknown ? (
        <em className="text-secondary italic text-sm">请到官方平台确认</em>
      ) : (
        <span className={st === "estimated" ? "italic" : st === "expired" ? "line-through" : ""}>
          {render ? render(field.value) : String(field.value)}
        </span>
      )}
      {/* 有来源时徽标可点击打开来源页（移动端无 hover，不用 tooltip 承载关键信息） */}
      {sourceUrl ? (
        <a href={sourceUrl} target="_blank" rel="noreferrer" onClick={(e) => e.stopPropagation()}>
          {badge}
        </a>
      ) : badge}
      {st === "expired" && field.evidence?.fetched_at && (
        <small className="text-xs text-secondary">更新于 {field.evidence.fetched_at}</small>
      )}
    </span>
  );
}
```

### 3.2 对话流组件（按 BFF 实际契约）

> **对话链路契约**（与 `src/wheretogo/bff/app.py` 实现一致，不是 SSE 直回）：
>
> ```
> POST /plans/{pid}/chat        → JSON decision：
>   { plan_id, intent, action, reply, constraints, constraints_patch,
>     ready_to_plan, auto_stream?, restart_stream? }
> decision.auto_stream    = true → POST /plans/{pid}/research-more  (SSE 深研续流)
> decision.restart_stream = true → GET  /plans/{pid}/stream         (SSE 全量重跑)
> ```
>
> - `pid = "new"` 时首条带约束的消息由服务端**自动建 plan** 并在 `decision.plan_id` 返回；前端收到后替换本地 planId 并更新 URL，后续轮次挂在真实 plan 上；
> - `decision.reply` 直接渲染为 assistant 气泡；
> - `streaming` 状态在 SSE 的 `done`/`error` 事件（或无流时 chat 响应返回）后才复位；
> - SSE 事件→组件映射见 §4.2。

```tsx
// components/chat/ChatPanel.tsx
"use client";

import { useState, useRef, useEffect } from "react";
import { useRouter } from "next/navigation";
import { motion, AnimatePresence } from "framer-motion";
import { MessageBubble } from "./MessageBubble";
import { QuickCommands } from "./QuickCommands";
import { ResearchProgress } from "./ResearchProgress";
import { consumeSSE } from "@/lib/sse";
import { chatTurn, streamUrl, researchMoreUrl } from "@/lib/api";
import type { CardPayload, ChatDecision } from "@/lib/types";

interface Message {
  id: string;
  role: "user" | "assistant";
  content: string;
  cards?: CardPayload[];      // node_output/interrupt/done 的卡片负载，字段一律经 FactField
  timestamp: string;
}

export function ChatPanel({ planId: initialPlanId }: { planId?: string }) {
  const router = useRouter();
  const [planId, setPlanId] = useState(initialPlanId ?? "new");
  const [messages, setMessages] = useState<Message[]>([]);
  const [input, setInput] = useState("");
  const [streaming, setStreaming] = useState(false);
  const [researchPhase, setResearchPhase] = useState<string | null>(null);
  const scrollRef = useRef<HTMLDivElement>(null);

  const pushAssistant = (content: string, cards?: CardPayload[]) =>
    setMessages((prev) => [...prev, {
      id: crypto.randomUUID(), role: "assistant", content, cards,
      timestamp: new Date().toISOString(),
    }]);

  // 消费 SSE 流：delta 追加到当前气泡，卡片事件挂载到当前气泡
  const pump = async (url: string, options?: RequestInit) => {
    const draft: Message = {
      id: crypto.randomUUID(), role: "assistant", content: "",
      timestamp: new Date().toISOString(),
    };
    setMessages((prev) => [...prev, draft]);
    const patch = () => setMessages((prev) => [...prev.slice(0, -1), { ...draft }]);
    await consumeSSE(url, {
      assistant_delta: (d) => { draft.content += (d as { text: string }).text; patch(); },
      research_progress: (d) => setResearchPhase((d as { phase: string }).phase),
      node_output: (d) => { draft.cards = [...(draft.cards ?? []), d as CardPayload]; patch(); },
      interrupt: (d) => { draft.cards = [...(draft.cards ?? []), d as CardPayload]; patch(); },
      done: (d) => { draft.cards = [...(draft.cards ?? []), d as CardPayload]; patch(); },
      error: (d) => {
        draft.content ||= (d as { message?: string }).message ?? "生成中断，请重试";
        patch();
      },
    }, options);
  };

  const handleSend = async () => {
    const text = input.trim();
    if (!text || streaming) return;
    setMessages((prev) => [...prev, {
      id: crypto.randomUUID(), role: "user", content: text,
      timestamp: new Date().toISOString(),
    }]);
    setInput("");
    setStreaming(true);
    try {
      const decision: ChatDecision = await chatTurn(planId, text);
      const pid = decision.plan_id ?? planId;
      if (decision.plan_id && planId === "new") {
        setPlanId(decision.plan_id);
        router.replace(`/chat?plan=${decision.plan_id}`);   // 后续轮次挂在真实 plan 上
      }
      if (decision.reply) pushAssistant(decision.reply);
      if (decision.auto_stream) await pump(researchMoreUrl(pid), { method: "POST" });
      else if (decision.restart_stream) await pump(streamUrl(pid));
    } catch {
      pushAssistant("网络异常，请稍后重试");
    } finally {
      setStreaming(false);
      setResearchPhase(null);
    }
  };

  useEffect(() => {
    scrollRef.current?.scrollTo({ top: scrollRef.current.scrollHeight, behavior: "smooth" });
```

### 3.4 主题转盘（服务端权威结果 + 前端纯动画）

> **设计原则**：转盘结果由服务端产生——`POST /rooms/{id}/theme/wheel`（DD-18）完成硬约束排除、偏好加权随机，并持久化 `wheel_spins`（上限 2 次 = 首次 + 一次反悔，超限返回 409）。前端**不做任何本地随机**，只根据服务端返回的主题计算目标角度并播放"转到指定结果"的动画。这样保证：① 同一房间所有成员看到同一结果；② "一次反悔"由服务端强制，刷新页面无法绕过（PRD §7.3.3"避免频繁重抽导致决策失效"）。

```tsx
// components/room/ThemeWheel.tsx
"use client";

import { useState } from "react";
import { motion } from "framer-motion";
import { spinWheel, ApiError } from "@/lib/api";
import type { WheelResult } from "@/lib/types";

interface ThemeWheelProps {
  roomId: string;
  onResult: (theme: string) => void;
}

export function ThemeWheel({ roomId, onResult }: ThemeWheelProps) {
  const [spinning, setSpinning] = useState(false);
  const [rotation, setRotation] = useState(0);
  const [result, setResult] = useState<WheelResult | null>(null);
  const [error, setError] = useState<string | null>(null);

  const spin = async () => {
    if (spinning) return;
    setSpinning(true);
    setError(null);

    // ① 先向服务端取结果（硬约束排除 + 偏好加权 + 次数控制）
    let wr: WheelResult;
    try {
      wr = await spinWheel(roomId);   // → { theme, weights, spins_left, excluded }
    } catch (e) {
      setSpinning(false);
      setError(e instanceof ApiError && e.status === 409
        ? "转盘次数已用完，请直接选择主题"
        : "转盘失败，请重试");
      return;
    }

    // ② 按服务端结果计算落点：等分扇区，指针指向选中项
    const themes = wr.weights.map((w) => w.theme);
    const idx = Math.max(themes.indexOf(wr.theme), 0);
    const seg = 360 / Math.max(themes.length, 1);
    const target = 360 - idx * seg - seg / 2;   // 选中扇区中心的绝对角度
    // 至少再转 5 圈，且最终模 360 精确落在 target（修复 v1.0 累加漂移 bug）
    setRotation((prev) => prev + 360 * 5 + (((target - prev) % 360) + 360) % 360);

    // ③ 动画结束后才展示结果
    setTimeout(() => {
      setSpinning(false);
      setResult(wr);
      onResult(wr.theme);
    }, 3000);
  };

  const themes = result?.weights.map((w) => w.theme) ?? [];

  return (
    <div className="flex flex-col items-center gap-6">
      {/* 转盘（等分扇区；权重只影响服务端抽取，不改变扇区大小） */}
      <div className="relative w-64 h-64">
        <motion.div
          className="w-full h-full rounded-full border-4 border-border overflow-hidden bg-card"
          animate={{ rotate: rotation }}
          transition={{ duration: 3, ease: "easeOut" }}
        >
          {themes.map((t, i) => {
            const angle = (360 / themes.length) * i;
            return (
              <div
                key={t}
                className="absolute inset-0 flex items-center justify-center"
                style={{ transform: `rotate(${angle}deg)` }}
              >
                <span
                  className="absolute text-xs font-medium text-primary"
                  style={{ transform: `translateY(-90px) rotate(${-angle}deg)` }}
                >
                  {t}
                </span>
              </div>
            );
          })}
        </motion.div>
        {/* 指针（自定义三角形，globals.css 中的 .clip-triangle） */}
        <div className="absolute top-0 left-1/2 -translate-x-1/2 -translate-y-2
                        w-4 h-6 bg-accent-coral clip-triangle" />
      </div>

      {error && <p className="text-sm text-accent-red">{error}</p>}

      {/* 结果：服务端返回 spins_left 控制反悔按钮（一次反悔 = 最多 2 次） */}
      {result && !spinning && (
        <motion.div
          initial={{ opacity: 0, scale: 0.8 }}
          animate={{ opacity: 1, scale: 1 }}
          className="text-center"
        >
          <p className="text-lg font-semibold text-primary">本次主题：{result.theme}</p>
          {result.excluded.length > 0 && (
            <p className="text-xs text-secondary mt-1">
              已按硬约束排除：{result.excluded.join("、")}
            </p>
          )}
          {result.spins_left > 0 ? (
            <button onClick={spin} className="mt-2 text-sm text-accent-blue underline">
              不满意？再转一次（仅一次机会）
            </button>
          ) : (
            <p className="mt-2 text-xs text-secondary">反悔次数已用完，可确认或改选其他主题</p>
          )}
        </motion.div>
      )}

      {/* 开始按钮 */}
      {!result && (
        <button
          onClick={spin}
          disabled={spinning}
          className="px-6 py-3 bg-accent-yellow text-primary font-medium rounded-card
                     disabled:opacity-50 hover:bg-accent-yellow/80 transition shadow-sm"
        >
          {spinning ? "转动中..." : "开始转动"}
        </button>
      )}
    </div>
  );
}
```

### 4.1 SSE 流式解析（与 web-v2 实现一致）

```typescript
// lib/sse.ts
export interface SSEEvent {
  event: string;
  data: unknown;
}

export async function* parseSSE(
  url: string,
  options?: RequestInit
): AsyncGenerator<SSEEvent> {
  const resp = await fetch(url, options);
  if (!resp.ok) {
    throw new Error(`SSE request failed: ${resp.status}`);
  }
  if (!resp.body) return;

  const reader = resp.body.getReader();
  const decoder = new TextDecoder();
  let buf = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buf += decoder.decode(value, { stream: true });
    const parts = buf.split(/\r?\n\r?\n/);
    buf = parts.pop() ?? "";

    for (const chunk of parts) {
      let event = "message";
      let data = "";
      for (const line of chunk.split(/\r?\n/)) {
        if (line.startsWith("event:")) event = line.slice(6).trim();
        else if (line.startsWith("data:")) data += line.slice(5).trim();
      }
      if (data) {
        try {
          yield { event, data: JSON.parse(data) };
        } catch {
          // Skip malformed JSON
        }
      }
    }
  }
}

export async function consumeSSE(
  url: string,
  handlers: Record<string, (data: unknown) => void>,
  options?: RequestInit
): Promise<void> {
  for await (const { event, data } of parseSSE(url, options)) {
    const handler = handlers[event] ?? handlers["*"];
    if (handler) handler(data);
  }
}
```

### 4.2 SSE 事件 → 组件映射表

**对话流（DD-15，`/plans/*`）**：

| SSE event | 负载 | 前端渲染 |
|-----------|------|----------|
| `assistant_delta` | `{text}` | 追加到当前 assistant 气泡（流式文字） |
| `clarify` | `{questions:[{q, options?}]}` | 气泡 + 选项按钮（可点选直接回复） |
| `node_output` | `{node, data}` | 按 node 渲染内嵌卡片（CityCard/TransportCard/PlanCard，字段一律 FactField） |
| `research_progress` | `{phase, message}` | `ResearchProgress` 进度指示 |
| `interrupt` | `{node, data}` | 探索版卡片 + 回填入口（`await_booking`，BYO Booking） |
| `done` | `{node, data.bundle}` | 完整 Trip Bundle 卡片 |
| `error` | `{code, message, degraded}` | 错误提示条 + 重试按钮；`degraded=true` 时提示降级内容仍可用 |

**房间流（DD-18，`/rooms/*`）**：

| SSE event | 负载 | 前端渲染 |
|-----------|------|----------|
| `room_state` | `{status}` | 房间状态条；触发路由守卫重新校验（§5.3） |
| `node_output` | 图节点原始输出 | 不直接渲染（由下列语义事件承载） |
| `activity_candidates` | `{candidates}`（≤10） | `ActivityCard` 列表（recommend 页） |
| `gathering` | 集合点/集合时间 | `GatheringInfo` |
| `member_routes` | `{routes}` | 成员路线卡（plan 页） |
| `itinerary` | 行程负载 | `VerticalTimeline` |
| `research_progress` | `{phase, message}` | `ResearchProgress` |
| `done` | — | 结束流式状态；重新拉取 `GET /rooms/{id}/plan` 刷新 |
| `error` | `{code, message, degraded}` | 错误提示 + 重试；`ROOM_BUSY` 提示稍候 |

### 4.3 多人实时同步策略

房间是多人协作场景，但 MVP **不引入 WebSocket**，采用"轮询 + SSE"两级策略：

| 场景 | 机制 | 说明 |
|------|------|------|
| 非流式页面（invite/member/summary/theme） | TanStack Query 轮询 | `GET /rooms/{id}` + `GET /rooms/{id}/summary`，`refetchInterval: 5000`，`refetchOnWindowFocus: true`；成员提交后便签 5s 内对其他人可见 |
| 流式阶段（recommend 推荐流、plan/modify 修改流） | SSE（§4.1） | 进度与结果实时推送 |
| SSE 不可用（部分微信内嵌浏览器/代理） | 降级纯轮询 | feature-detect `ReadableStream` 不可用时，`/recommend` 等页面改为 3s 轮询 `GET /rooms/{id}` + `GET /rooms/{id}/plan`，状态推进后停止 |
| `member_token` 传递 | 仅 POST/PUT body | `members`/`vote` 等成员操作放 body；GET 资源不带 token（房间数据对持邀请链接者可见，与 PRD 匿名邀请制一致；`/share` 端点服务端已脱敏） |

### 4.4 API 连接策略（v1.2 联调结论）

| 环境 | 连接方式 | 说明 |
|------|----------|------|
| 本地开发 | **前端直连 BFF**：`.env.local` 设 `NEXT_PUBLIC_API_BASE=http://localhost:8000`，BFF 经 `CORSMiddleware` 放行 `localhost:3000`/`127.0.0.1:3000` | Next 16 dev rewrites 代理对慢请求（>25s 的 chat 决策）报 `ECONNRESET`、对 SSE 缓冲不转发，**不可用于联调** |
| 生产部署 | 同源 `/api/*` 反向代理（`next.config.ts` rewrites 或网关），删除 `.env.local` 即回退 | 跨源部署时按域名收紧 BFF `allow_origins` |

另：`next.config.ts` 必须配置 `allowedDevOrigins: ["127.0.0.1", "localhost"]`——Next 16 默认拦截跨源 dev 资源（HMR/客户端 chunk），否则以 `127.0.0.1` 访问时页面 SSR 正常但 hydration 静默失效（联调实测，无任何报错）。

### 5.2 双模式信息架构（IA）

"双模式统一体验"的具体含义 = **同一设计系统 + 同一对话基础设施 + 明确的模式分工与转换路径**：

| 页面 | 职责 | 说明 |
|------|------|------|
| `/chat` | **规划驱动页**（跨城模式主入口） | 对话流为主体，结构化卡片内嵌于消息流；`planId=new` 起聊，首条带约束消息服务端自动建 plan |
| `/plan/[id]` | **Trip Bundle 视图页** | 桌面（≥1024px）左右分栏：Bundle 卡片 \| ChatPanel（`planId=当前 plan`，可继续多轮修改）；移动端 Bundle 全屏 + 底部"继续聊"抽屉拉起 ChatPanel |
| `/room/[id]/*` | **市内多人协作** | 房间状态机驱动（§5.3），ModifyInput 即房间内对话修改入口 |
| 模式转换 | chat → room | 对话中识别到多人市内意图时，引导创建房间（`POST /rooms` → 跳 `/room/[id]/invite`） |
| 模式转换 | room → share | 房间 PUBLISHED 后生成分享页，可回流邀请新成员 |

### 5.3 房间状态 → 路由映射（路由守卫）

进入任意 `/room/[id]/*` 页面时先 `GET /rooms/{id}`，当前路由与状态不符时重定向到状态对应页：

| room.status | 对应路由 | 说明 |
|-------------|----------|------|
| `draft` | `/room/[id]/invite` | 刚创建，邀请成员 |
| `collecting` | 未填信息 → `/room/[id]/member`；已填 → `/room/[id]/summary` | 按当前用户（localStorage token）是否已提交区分 |
| `theme_selecting` | `/room/[id]/theme` | 直选/投票/AI 推荐/转盘 |
| `recommending` | `/room/[id]/recommend` | SSE 推荐流 |
| `activity_selected` | `/room/[id]/activity/[aid]` | 详情 + 共同决策 |
| `planning` | `/room/[id]/plan` | 路线 + 行程生成 |
| `published` | `/room/[id]/plan`（+ `/room/[id]/share` 入口） | 最终行程可分享 |
| `expired` | `/room/[id]` | 只读过期页：全站操作禁用 + "房间已过期"提示条 |

### 5.4 匿名会话与 token 策略（PRD §7.1.2：未登录可用）

- **创建房间**：`POST /rooms` → `{room_id, invite_code, invite_url, 创建者 member 信息（含 member_token）}`；
- **加入房间**：邀请链接 `/room/[id]/invite?code={invite_code}` → `GET /rooms/by-invite/{code}` 解析 → 填昵称 → `POST /rooms/{id}/members` → `{member_id, member_token}`；
- **本地持有**：`localStorage["gomate:room:{roomId}"] = { member_id, member_token, nickname }`；房间内成员操作（更新信息/投票）从 localStorage 取 token 放 body；
- **token 丢失**（换设备/清缓存）：凭邀请链接重新加入。MVP 接受因此产生的重复成员，昵称认领留待后续版本；
- **房间有效期**：默认保留至活动结束后 7 天（PRD §7.1.2），过期后进入 `expired` 只读态（§5.3）。

### 5.5 成员信息表单（MemberForm，PRD §7.2）

| 字段 | 输入方式 | 说明 |
|------|----------|------|
| 昵称 | 文本 | 必填 |
| 出发地 | 三选一（PRD §7.2.1） | ① 使用当前位置（Geolocation API，**必须用户授权**，PRD §15.4）；② 搜索地铁站/商圈/地标（高德 POI 搜索）；③ 手动输入区域。**不要求精确住址**，仅区域级 |
| 空闲时间 | 时间选择器 | 最早可出发时间 + 最晚结束时间（PRD §7.2.2） |
| 兴趣偏好 | 快捷标签多选 + 自然语言补充 | 标签见 `lib/constants.ts`（看展/公园/Citywalk/做手工/咖啡探店/吃饭聊天/逛市集/看演出/运动/拍照/逛书店/桌游/宠物友好/夜间活动） |
| 硬约束 | 快捷标签多选 | 不接受户外/不想走太多路/不吃辣/预算上限/需早睡回家/无障碍（PRD §7.2.3，与兴趣分开展示） |
| 预算范围 | 区间选择 | 可选 |
| 出行方式偏好 | 单选 | 公交地铁/打车/步行骑行优先 |
| 补充说明 | 文本 | 可选 |

提交：首次 `POST /rooms/{id}/members`，修改 `PUT /rooms/{id}/members/{mid}`（body 带 `member_token`）。

## 9. 风险

| 风险 | 缓解 |
|------|------|
| 手绘风格实现成本高 | MVP 用 Tailwind + 少量内联 SVG 装饰 + font-handwrite 标题，不做全套插画 |
| 手写字体国内加载失败 | `next/font/local` 自托管 woff2（§2.3），缺失时静默降级系统字体 |
| 移动端地图性能 | 按需加载 AMap，默认用静态图 + URI 深链 |
| SSE 在微信内浏览器兼容 | 降级为轮询（§4.3，feature-detect 自动切换） |
| 转盘动画复杂度 | Framer Motion 单组件封装，不做 Canvas |
| 多人同步实时性 | 5s 轮询 + 窗口聚焦刷新；MVP 不引入 WebSocket |
| 新旧前端切换 | `web-v2/` 独立部署，旧 Demo 保留，灰度切流 |
