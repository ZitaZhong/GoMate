# DD-00 总体详细设计（集成与联调）· 详细设计

**详细设计系列 · 集成总纲 · v1.0 · 2026 年 7 月**

> 本文是详细设计系列的**集成总纲**：把 DD-01 ~ DD-17 十七个模块（含 v2 的对话式 Copilot / 记忆 / 实时深度研究）串成一个**可端到端跑通、能支撑最终产品**的系统。回答三个问题：① 各模块**如何连接**（接口/数据/状态如何流转）；② 整体**能否支撑产品**（对 PRD 指标逐条兜底）；③ 集成还有哪些**待对齐项**（留给优化轮）。
>
> **读法**：先读 DD-01（数据契约）、DD-02（编排契约）、DD-03（证据契约）建立全局语言，再按本文 §3 端到端主流程把其余模块对号入座。
> **模块清单**：DD-01 数据模型 · DD-02 编排 Planner · DD-03 证据护栏 · DD-04 Provider/AI · DD-05 检索 · DD-06 活动情报 · DD-07 约束/多人 · DD-08 目的地/城市档案 · DD-09 交通 · DD-10 回填 · DD-11 住宿/接驳/餐饮 · DD-12 时间线/校验/天气 · DD-13 组装/前端/提醒 · DD-14 扩展 · **DD-15 对话式 Copilot · DD-16 记忆 · DD-17 实时深度研究（v2 新增）**。

## 2. 两条数据流（读写解耦，全局主轴）

| 流 | 触发 | 路径 | 特征 |
|---|---|---|---|
| **情报生产流**（异步批量） | Celery 定时 | DD-06：注册表→抓取→抽取→归一→去重→`enforce_provenance`→`embed`→写 `activities` | 慢而脏；预热库 |
| **规划快路径**（同步/秒级） | 用户对话 | DD-02 逐节点读 activities + DD-05 检索 + 确定性计算 → **秒级垫场** | 快；先给库结果占位 |
| **实时深路径**（同步/流式，v2） | 每次相关需求 | DD-17 有界迭代深研(联网多源→官方核实→抽取定级) → `ingest_realtime` 写库 → DD-05 复检融合 | 最新；强制全量、有界、流式 |

> v1.1 的"规划流绝不实时"在 v2 演进为**快路径垫场 + 深路径每次强制全量实时深研**（见 v2 增补 D5）；**写 `activities` 仍统一走 DD-06 管线**（批量或 `ingest_realtime`），读写解耦的定级/去重不变。

## 3. 端到端主流程（状态字段级时序）

### 3.1 探索阶段（约束 → 探索版 → 中断）

```text
⓪ 对话(DD-15): 用户聊天自然语言多轮澄清（命中 DD-16 记忆的槽位不问）→ 压成 research brief
① BFF POST /plans ──启动──► DD-02 graph(thread_id=plan:{id})；会话首 load_memory(DD-16)→memory_ctx
② parse   (DD-07): constraints原始+party ─► constraints结构化(DD-01§8.1)+query, warnings
③ discover(DD-08): constraints ─并行扇出─► candidate_cities[]
      每候选城并发: estimate_door_to_door(DD-09粗估) + weather(DD-04) + retrieve_activities(DD-05)
      ─屏障reducer合并─► 3 张城市卡(带 evidence)
④ research(DD-08): candidate_cities ─► activities[]；**每轮强制 deep_research(DD-17 有界迭代: 多源深搜→官方核实→定级→ingest_realtime 入库)**；DD-05 检索作库垫场并与深研结果融合
⑤ transport(DD-09): constraints+candidate_cities ─► transport_options{门到门,策略卡,prefill,presale}
⑥ await_booking(DD-02): compose_explore(DD-13) ─► bundle(explore)
      → interrupt{explore_bundle, prefill, presale_reminders} → 持久化checkpoint → 退出
   ├─ SSE 推 explore 版；前端 FactField 渲染六态(DD-03§7 / DD-13)
   └─ DD-13 起售提醒入队: transport_options.presale → reminders(type=presale)(Celery beat)
```

### 3.2 回填（中断期，用户在官方平台买票后）

```text
⑦ 回填(DD-10): 文本/截图(OSS)/链接 ─抽取(DD-04 OCR/小模型)─► 草稿(needs_review)
      ─用户逐字段确认─► bookings(confirmed=True, evidence=confirmed_by_user)
      ─► resume payload(DD-02§6.2)
   (DD-14 扩展亦走此管道)
```

### 3.3 确认阶段（恢复 → 确认版）

```text
⑧ BFF POST /resume ─Command(resume=bookings)─► DD-02 从 checkpoint 续跑(不重算②~⑤)
⑨ hotel   (DD-11): bookings+candidate_cities ─► hotel_area(区域卡, 返程枢纽来自 bookings/transport)
⑩ mobility(DD-11): bookings+hotel_area+activities ─► local_routes[](DD-04 route/matrix)
⑪ dining  (DD-11): hotel_area+timeline草稿+constraints ─► dining[](DD-05 retrieve_dining)
⑫ timeline(DD-12): bookings锚点(DD-10 to_timeline_anchors)+activities+dining+local_routes
      ─贪心排点─► timeline_slots[]
⑬ validate(DD-12): timeline+constraints ─► validation{ok,issues}
      ─条件边(DD-02)─► ok→compose | RETURN_TIGHT→transport | 其它硬冲突→timeline
⑭ compose (DD-13): 全部产物 ─闸三断言(DD-03)─► bundle(confirm) → 写 trip_bundles
   ├─ SSE done；确认版计划卡(逐小时时间线+已确认花费+预估待花+风险+备选)
   └─ DD-13 生成 ICS 订阅 + Web Push/邮件提醒(DD-01 reminders)
⑮ 会话结束/确认: extract_and_write(DD-16) 抽取稳定偏好写 user_memory(覆盖语义) → 下次会话可察觉
```

### 3.4 重规划（贯穿）

```text
天气检查(DD-12, 行前72h/24h) / 信息变更 / 手动刷新
   ─► DD-02 trigger_replan(reason, from_node) ─► 从 timeline/dining/discover 重入
   只重算受影响子图；已确认 bookings 恒不动。
```

## 5. 证据流全景（贯穿始终）

```text
产生: DD-06 抽取 / DD-09 计算 / DD-10 回填 / DD-11 地图  ── 各自带 source_type

最终闸: DD-13 compose 前 assert_no_fabricated_transport(交通/票价/余票禁 llm)

```

**硬 KPI 落点**：`compose` 出稿断言计数恒为 0 → 对应 PRD"未确认字段被误展为已确认 = 0"。

## 6. 三条硬约束的端到端保障（谁共同兜底）

| 硬约束 | 共同保障的模块 |
|---|---|
| **不做交易** | DD-09（策略卡+深链，不抓余票）+ DD-10（回填，不代购）+ DD-14（扩展不自动登录/购票）+ DD-13（提醒只给官方入口） |

| **轻后端重证据** | DD-01（一库三用）+ DD-04（缓存/配额）+ 读写解耦（DD-06 异步 vs DD-02 只读）+ DD-06 情报运营（护城河） |

## 8. 产品支撑性论证（能否支撑 PRD 指标）

| PRD 指标 | 由哪些 DD 支撑 | 结论 |
|---|---|---|
| 北极星：每周确认的可执行 Trip Bundle 数 | 全链（DD-02 编排 + DD-13 确认版） | ✅ 端到端闭环打通 |
| 15 分钟内从"没目的地"收敛到 1 候选城 | DD-07 约束 + DD-08 目的地（活动驱动）+ DD-05 检索质量 | ✅ 效果核心已强化 |
| 对话式多轮（模糊→具体→精细） | DD-15 Copilot + DD-16 记忆 | ✅ v2 |
| 实时获取最新活动/出行信息 | DD-17 有界迭代深研（每次强制全量） | ✅ v2 |
| 越用越懂你（跨会话喜好/历史） | DD-16 Mem0 长期偏好 | ✅ v2 |
| 交通回填完成率 | DD-09 预填清单 + DD-10 极致顺滑回填 + DD-14 扩展 | ✅ |
| 核心活动官方来源比例 | DD-06 情报流水线 + DD-03 定级 | ✅ 可量化埋点 |
| 未确认字段被误展为已确认 = 0 | DD-03 三闸 + DD-13 最终闸 + 前端六态 | ✅ CI 硬门禁 |
| 日程硬冲突率 | DD-12 校验器 HARD_CONFLICT 埋点 | ✅ |
| 门到门时间偏差 | DD-09 确定性门到门 | ✅ |
| 位置匹配/回填解析准确率 | DD-11 地图 + DD-10 抽取+确认闭环 | ✅ |
| 多人公平性（v0.2） | DD-07 聚合 + 公平性 | ✅ 数据模型已备 |

> 结论：**十七模块在数据、编排、证据三条契约下环环相扣，能支撑 PRD 的北极星与可信度硬 KPI**；效果优先项（检索质量 DD-05、活动情报 DD-06、实时深研 DD-17）为护城河重点设计；v2 补齐了**对话式交互（DD-15）、跨会话记忆（DD-16）、实时最新（DD-17）**三项。

## 9. 集成待对齐清单（★ 交优化轮逐项消解）

> 并行编写产生的细节偏差，主干无碍，但需在优化轮统一以保证"准确无误"。

| # | 待对齐项 | 涉及 | 处置方向 |
|---|---|---|---|
| 1 | 门到门粗估接口命名/签名 | DD-08 用 `estimate_door_to_door`，DD-09 引擎为 `door_to_door` | DD-09 显式暴露 `estimate_door_to_door()`（粗估档）供 DD-08，二者共用 leg 结构 |

| 7 | SSE 事件 schema | DD-02 §11 ↔ DD-13 渲染契约 | 核对 event/node/data 字段一致 |
| 8 | 城市卡 evidence 透传 | DD-08 城市卡 ↔ DD-03 六态 | 核对“理由透传活动 evidence、估算字段=estimated” |

> **优化轮已完成**（本清单已逐项消解）：
