# DD-05 检索服务（混合检索 + 重排）· 详细设计

**详细设计系列 · 效果核心文档 · v1.0 · 2026 年 7 月**

> 本文是 v1.1 增补 A 的落地：把 `activities` / POI 从"存着"变成"**推得准**"。提供 **embedding → 两阶段（混合召回 + 交叉重排）→ 候选** 的检索服务，是产品正面回应竞品"半吊子 / 排列组合 / 找餐馆不妥帖"的关键模块。
>
> **上游依据**：v1.1 增补 A、《向量库调研》、DD-01（`activities.embedding/search_tsv/索引`）、DD-03（结果透传 evidence）、DD-04（embedding/rerank 作为 Provider）。
> **下游消费者**：DD-08（目的地发现/活动研究）、DD-11（餐饮/POI 检索）、DD-02 `research`/`dining` 节点。
> **一句话**：**召回靠"地理+结构化+语义"三重过滤的混合检索，排序靠交叉编码重排 + 用户偏好——个性化、不编造、不同质。**

---

## 1. 模块职责与边界

| 项 | 说明 |
|---|---|
| **职责** | 提供活动/餐厅/POI 的**高质量检索**：embedding 生成、混合召回（dense+sparse+RRF）、交叉编码重排。 |
| **边界内** | embedding 服务、召回 SQL、RRF 融合、重排、查询构造、检索 API、降级。 |
| **边界外** | 活动数据的抓取/入库（DD-06）、城市打分（DD-08）、路线计算（DD-11）。本模块**只读** `activities`（读写解耦）。 |
| **架构位置** | DD-04 之上的检索能力；被 DD-02 `research`/`dining` 节点调用。 |

---

## 2. 设计目标与非目标

**目标**：① 召回**全**（专有名词/罕见活动不漏）+ 排序**准**（最相关排最前）+ **个性化**（按用户偏好，不千篇一律）；② 检索 top-K 延迟可控（探索版秒级）；③ 结果**透传** `activities.evidence`，不新造事实。

**非目标**：❌ 不产生新事实（证据来自 DD-06 写入的活动）；❌ 不写 `activities`；❌ v0.1 不追求十亿级规模（pgvector 足够，见 DD-01 §10.3）。

## 3. 服务接口（供 DD-08 / DD-11 调用）

```python
                                  constraints: dict, center=None, top_k: int = 20) -> list[ActivityCandidate]:
        """活动检索：混合召回 top-100 → 重排 → top_k。结果含原 evidence。"""

    async def embed(self, texts: list[str]) -> list[Vector]:      # BGE-M3 dense（供 DD-06 入库）
    async def rerank(self, query: str, docs: list[str]) -> list[float]:  # BGE-reranker 分数
```

`ActivityCandidate` = `activities` 行 + `rerank_score`，其 `evidence` 原样透传（DD-03）。

## 4. embedding 服务（BGE-M3）

| 项 | 规格 |
|---|---|
| 模型 | **BGE-M3**（1024 维，dense+sparse+ColBERT 一体，自托管）；备选 Qwen3-Embedding |
| 部署 | 独立推理服务（GPU 或 CPU 起步），经 DD-04 Provider 封装（`op="embed"`，带缓存） |
| 版本 | 写入 `activities.embedding_version`；**入库/查询同模型同维度**（DD-01 铁律） |
| 换模型 | 新 `embedding_version` → 后台批量重嵌 → 双跑校验 → 切换（DD-01 §10.1） |
| 稀疏 | v0.1 用 PG `tsvector`（`search_tsv`）；未来可切 BGE-M3 sparse 输出零成本升级 |

**待嵌文本构造**（DD-06 入库时用）：`title + " " + venue + " " + category + " " + price_text`（拼接核心可检索字段）。

## 5. 召回层（混合检索，一条 SQL 打三重条件）

### 5.1 稠密召回（带硬过滤）

```sql
SELECT id, title, verification_status, embedding <=> :q_vec AS dist
FROM activities
WHERE city_code = :city
  AND start_at BETWEEN :wk_start AND :wk_end
  AND verification_status IN ('official_source_confirmed','public_source_observed')
  AND expires_at > now()
  AND (:center IS NULL OR ST_DWithin(location, :center, :radius_m))  -- 地理可选
ORDER BY embedding <=> :q_vec
LIMIT 100;
```

### 5.2 稀疏召回（BM25/全文，同硬过滤）

```sql
SELECT id, ts_rank(search_tsv, plainto_tsquery('simple', :q_text)) AS bm25
FROM activities
WHERE city_code = :city AND start_at BETWEEN :wk_start AND :wk_end
  AND expires_at > now() AND search_tsv @@ plainto_tsquery('simple', :q_text)
ORDER BY bm25 DESC LIMIT 100;
```

### 5.3 RRF 融合

```python
from collections import defaultdict
def rrf(rank_lists: list[list[str]], k: int = 60) -> list[str]:
    scores = defaultdict(float)
    for ranks in rank_lists:
        for pos, doc_id in enumerate(ranks):
            scores[doc_id] += 1.0 / (k + pos)
    return sorted(scores, key=scores.get, reverse=True)
```

> **硬过滤铁律**：`verification_status` 过滤在召回层强制执行——核心活动只来自官方/公开确认源，**不给 LLM 编造留位**（呼应 DD-03）。

## 6. 重排层（BGE-reranker-v2-m3）

```python
def rerank_query(constraints: dict) -> str:
    """把用户约束+偏好拼成重排 query，实现个性化排序。"""
    return (f"周末{constraints.get('interests')} 预算{constraints['budget_band']} "
            f"忌讳{constraints.get('dietary')} {constraints.get('query','')}")

def rerank_text(a: "ActivityRow") -> str:
    return f"{a.title} {a.venue} {a.category} {a.price_text}"

async def retrieve_activities(city, weekend, constraints, center=None, top_k=20):
    q_vec  = (await svc.embed([constraints["query"]]))[0]
    dense  = dense_recall_sql(city, weekend, q_vec, center)   # center 由 DD-08 传入(城市中心/活动聚集点)，非用户 constraints
    sparse = sparse_recall_sql(city, weekend, constraints["query"])
    fused  = rrf([dense, sparse])[:100]
    rows   = load_rows(fused)                          # 批量取回 activities 行（含 evidence）
    scores = await svc.rerank(rerank_query(constraints), [rerank_text(r) for r in rows])
    ranked = [r for _, r in sorted(zip(scores, rows), key=lambda x: -x[0])]
    return ranked[:top_k]                              # evidence 原样透传
```

## 7. 餐饮 / POI 检索（DD-11 复用，修"找餐馆不妥帖"）

- 召回：高德 POI（DD-04 `poi_search`，按 `near` + 餐饮类目 + 半径）；
- 重排 query 强调**动线契合**：`rerank_query_dining = f"距离{near}近 {cuisine偏好} 排除{dietary忌讳} {meal_slot}"`；
- 重排文本含 POI 名/类目/距离桶；**距离作为重排强特征**（动线契合度）；
- 永远保留一个 `is_fallback=True` 稳妥备选（DD-11）。

> 与"丢一个评分榜单"的区别：我们按**动线 + 偏好 + 忌讳**重排，而非只看评分——这正是 v1.1 A 承诺修掉的竞品短板。

## 9. 降级（DD-04 五件套之上）

| 失效 | 降级 |
|---|---|
| embedding 服务不可用 | 退化为**纯 BM25 召回**（`search_tsv`），排序用 bm25 |
| rerank 服务不可用 | 退化为 **RRF 融合序**（不重排），标注 |
| 二者都不可用 | 退化为"结构化过滤 + `start_at` 排序"，仍可用 |
| 召回为空 | 返回空 + 触发 DD-06 补搜 / 输出"官方源清单 + 关键词"（v1 韧性） |

## 10. 效果与验收标准（DoD）

1. **召回全**：构造"专有活动名"查询，纯 BM25 能召回，纯稠密漏，RRF 融合命中（对照测试）。
2. **重排准**：标注小规模 golden set（query→相关活动），重排后 NDCG@10 显著高于仅 RRF（量化目标：+相对 15%+）。
3. **个性化**：同城不同偏好（"展览" vs "演出"）返回明显不同排序（非同质）。
4. **不编造**：召回层过滤后，结果 `verification_status` 全为官方/公开观察，无 `estimated`/`llm`。
5. **延迟**：top-20 端到端 p95 < 300ms（含 embed 缓存命中）；embed/rerank 走 DD-04 缓存。
6. **降级**：mock 掉 rerank 服务，退化为 RRF 序仍返回结果。

## 11. 开发任务拆解

1. BGE-M3 embedding 推理服务 + DD-04 Provider 封装（1.5d）

6. 降级路径 + 单测（0.5d）

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 中文 `simple` 分词召回有限 | 需要时上 `zhparser`/`pg_search` BM25（DD-01 §2 预留） |
| rerank 推理成本/延迟 | 只对 top-100 重排；结果缓存；GPU 或轻量模型 |
| embedding 换模型导致检索错乱 | `embedding_version` 隔离 + 全量重嵌双跑校验（DD-01） |
| golden set 缺失无法量化"准" | v0.1 先小规模人工标注，纳入运营 |

---

> 本模块是"效果优先"的核心承载。检索质量的量化（NDCG/召回率）应作为产品"不做半吊子"的持续回归指标。

## 13. v2 增补：库结果垫场 + 每次强制全量深搜融合（对齐 DD-17，v2 强制全量）

- **v2 决策：每次相关检索都并行强制全量深搜**（不再"库够就跳过"）。`retrieve_activities` 的库检索结果**作为即时垫场秒级返回**，同时 DD-02 `research` 节点调 DD-17 `deep_research` 跑全量深搜。
- `retrieve_activities` **增返回**：`count`、`stalest_fetched_at`（供展示/融合参考，**不再用于跳过深搜**的门控）。
- **融合**：DD-17 实时入库后调 `svc.embed` + 本模块**复检召回**，与库垫场结果按 RRF 融合去重重排（新入库活动 evidence 照常透传；深搜结果通常更新更全，融合时优先）。
- 本模块仍**只检索、不抓取**（职责单一）；`center` 入参见 §3/§6（由 DD-08 传入，非用户 constraints）。
