# 「周末去哪儿」技术架构 v2 增补：对话式规划 + 记忆 + 实时深度研究

**版本 v2.0 · 因产品评审否决 v1.1 取舍而立 · 2026 年 7 月**

> **背景**：产品评审明确否决 v1.1 的三项取舍——"前端克制（无聊天框）/ 读写解耦（不做实时深搜）/ 记忆延后 v0.2"。评审要求：① **对话式 agent 聊天框**，自然语言、真多轮、从模糊到具体再到精细；② **跨会话记忆**（察觉用户喜好与历史）；③ **深度研究 + 实时联网**获取最新信息。
> **本文作用**：确立 v2 三项能力升级的架构决策，并索引对现有详细设计（DD-01 ~ DD-14）的改动；新增能力的详细设计见 DD-15/DD-16/DD-17。
> **不变的底线**：产品的三条硬约束（不做交易 / 证据优先 / 轻后端重证据）**不变**；尤其"证据优先"约束**实时深搜**的实现方式（见 D4）。

## 1. 为什么护栏不能动（D4 的理由，澄清"实时"≠"编造"）

竞品与开源调研已反复证明：通用大模型和多数 AI 旅游产品翻车的**根因**就是"把实时搜到的片段当事实 → 编造车次/航班/营业时间"（"第一批 AI 旅游受害者"、"济南直飞海拉尔"假航班号等）。

我们加实时深搜，目标是"**实时拿到最新、且能追溯到官方来源**"的信息，而**不是**变成又一个会编的 chatbot。因此：

- 深搜产出的每条事实**一律带 `evidence` + 六态**；
- **未回官方核实**的只能是 `public_source_observed` / `unknown`，**不得展示为已确认**；
- **交通票价 / 余票永不由模型生成**（DD-03 闸三不变）；
- 搜索结果**仅用于找官方入口**，核心事实回官方来源核实。

> **这是把"实时"与"可信"同时拿到的唯一方式**，也是我们区别于"半吊子会编"竞品的护城河。若产品要放开此约束，须显式决策并承担幻觉风险。

## 2. v2 数据流（对话 + 混合新鲜度）

```text
用户在聊天框输入自然语言（任意粒度）
        │
        ▼
[DD-15 对话 Copilot] 解析意图/粒度 + 澄清（真多轮）
        │  ├─(会话开始)读长期记忆 [DD-16 Mem0] → 注入偏好/历史
        │
        ├─ 快路径: [DD-05 检索] 预热库[DD-06] ─► 秒级卡片（够用即返回）
        │
        └─ 深路径(每次强制全量): [DD-17 实时深度研究]
                多源联网深搜 → 官方核实 → 抽取 → 定级(DD-03) → 实时入库(DD-06管线)
                → [DD-05 复检召回] → 流式进度 + 最新结果
        │
        ▼
[DD-02 编排] 对话驱动的两段式（每轮 interrupt/resume；可回退可重规划）
        │
        ▼
[DD-13 前端] 聊天界面 + 卡片内嵌（证据六态可视）+ 深搜进度流式
        │
        ▼
(会话结束/关键节点) [DD-16] 抽取新偏好/事实 → 写 Mem0（带覆盖语义）
```

**关键变化**：v1.1 的"规划流只读、绝不实时"演进为"**快路径读预热库垫场（秒级），深路径每次强制全量实时深搜并入库（流式）**"。读写解耦仍在（深搜入库仍走 DD-06 统一抽取/定级/去重管线），但**新增了每次需求都执行的同步实时研究**。

## 4. 落地节奏（v0.1 即含）

v0.1 交付即包含：**对话式 Copilot（真多轮，从模糊到精细）+ 会话记忆 + 基础长期偏好（Mem0）+ 实时深度研究（触发式 + 护栏 + 流式）**。

仍可延后：预算滑杆、双栏交互地图、拖拽编辑等**富交互**（不影响"对话 + 实时 + 记忆"三项核心能力）。
