## 一、产品理解 → 验证模型

从 PRD 提炼的六条可断言不变量（验收套件围绕它们构造）：

1. **两段式**：交通未确认只给策略（interrupt），回填后才出精确计划（done）——B1/B6
2. **诚实**：证据必在六态内（B4）、confirmed_by_user 只能来自用户（B8/D2）、不造票价（B5）、无数据给官方源而非编造（G1）、入库数据时间段合法（G3）
3. **跨城决策**：不判同城（C1）、门到门双模式非零（C2）、长途飞机门到门应快于高铁（C3）、预填发到站（C4）
4. **回填**：粘贴文本自动结构化（D1）、初稿须经确认（D2）
5. **对话**：人话进、约束出（E1）、语义不跑偏（E2）、回填意图不丢（E3）、问答命中已有数据（E4）、乱输入有兜底（E5）
6. **多人**：邀请可区分（F1）、聚合数学正确（F2）、不泄漏个体隐私（F3）

## 三、FAIL 项定级与修复建议

| 用例 | 定级 | 说明 |
|---|---|---|
| D2 | **P1（诚实 KPI）** | 机器抽取=AI 产出，按自家 Guard 纪律最高只能 estimated；现在用户没点确认就写 confirmed_by_user，违背"识别结果经你确认后生效"（原则三）。修法：import 初稿标 estimated/unknown，确认动作落地后才转 confirmed_by_user |
| E2 | P1 | "目的地换 X"patch 为空——修改类对话完全不生效。需识别"目的地/去 X"语义并写 target_city_code |
| E4 | P1 | 问答检索与用户查询脱节："莫奈"应命中库内"中华艺术宫 莫奈与印象派大师展"。ask_info 应答路径需接检索服务 |
| F1 | P2 | 匿名标签按成员序号生成（同伴1/同伴2…） |
| G4 | P2 | §06 探索版缺"待确认清单"——两段式体验的关键钩子（用户下一步该干什么）目前靠 warning 文案游离表达 |
