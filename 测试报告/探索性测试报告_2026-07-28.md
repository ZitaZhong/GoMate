## 3. 本轮发现并修复的缺陷

### 缺陷 #1：疑问句被约束纠偏劫持——「门票多少钱」永远得不到回答
- **现象**：用户问「万兽之王演唱会门票多少钱」，系统回复「已记下：从上海出发；2人；想玩演唱会…」并开始重新规划，问题被吞掉
- **根因**：①handle_turn 的 probe 纠偏只要抽出兴趣词就把 ask_info 改为 provide_constraints，不问是不是问句；②LLM 意图指南对"含约束的疑问句"归类不稳定
- **修复**：疑问词判别（多少/什么/几点/在哪/吗/呢/？）——纯问句（无硬约束）留在 ask_info；硬约束挂问句尾巴（"从上海出发想看展，门票多少"）仍优先约束捕获（兼容既有设计）；LLM 意图指南强化示例。新增 2 条回归测试
- **复验（live）**：同一句话 → intent=ask_info，回答「库内暂时没有该活动的价格信息…请发官方页面链接核实…以官方页面为准」——**不编造价格**，证据红线成立

### 缺陷 #2：跨城分享页对已完成规划显示「没有可分享的内容」
- **现象**：/plan/3101（已有完整探索版）的分享页显示空态
- **根因**：share-view 只读 /state（图 values 不含 bundle 大对象，与此前 plan 页同源的坑），且按旧嵌套键（explore.core_activities 等）取值，与 compose 实际顶层键不匹配
- **修复**：share-view 增加 /bundle 兜底（与 plan 页一致）；按真实契约渲染（城市/主题/时间窗/活动名白名单脱敏）
- **复验（浏览器）**：分享页正确显示 杭州/博物馆·演唱会之旅/8/7周五出发/8/9周日返程/5 个行程亮点（带证据徽标）/disclaimer；预算零泄漏

## 4. 观察项（非缺陷，如实记录）

| 项 | 说明 | 建议 |
|---|---|---|
| 不存在 plan 页仍显示「分享/订阅日历 ICS」链接 | 纯展示层小瑕疵，点击无害 | 低优先级：plan 404 时隐藏操作区 |
| 房间无「移除成员」端点 | 误加成员（昵称打错/测试号）不可移除 | 产品决策：MVP 可接受重复成员，后续加移除/改名 |
| 投票 tally 无独立 GET | 他人投票结果只在自己投票响应里可见，轮询 getRoom 不含 tally | P2：summary 加 tally 字段 |
| 同一浏览器扮演多成员 | localStorage 每房间单身份，重复加入会覆盖本机身份 | 匿名 MVP 设计如此；文档提示"一设备一人" |
| 对话刷新后消息区为空 | 消息存 plans.conversation 但前端不回放 | P2：/chat 恢复时回放最近 N 轮 |
| ask_info 答案依赖库内数据 | 无数据时诚实说"没有"并引导官方链接（设计意图） | 配置真实 search key 后覆盖更好 |

## 5. 结论

系统在**正常流、异常输入、中途反悔、回退、组合意图切换**下整体健壮：24 项异常输入全部正确拒绝或降级，两条主链路（对话/房间）各种走法无崩溃无 500，证据六态与脱敏红线在所有抽查点成立。本轮发现 2 个真实缺陷（问答劫持、分享页数据源），均已修复并复验，回归 365 全绿。

**剩余风险集中在数据面而非功能面**：离线兜底数据时效（部分活动偏旧）、房间餐饮 POI 未注入（换餐厅无真候选）、DD-16 记忆待账号体系——见《架构审计与修复报告》§4。
