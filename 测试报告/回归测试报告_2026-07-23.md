## 一、总体结论

**从最终用户视角：本轮验收不通过，不予放行。** 用户在界面上实际能用到的东西仍然不合格——最典型的就是对话框：无论后端理解得对不对，界面上只回一行"（意图：X · 动作：Y）"调试文本，这不是可交付的产品形态。

**从 API/工程修复验证视角：修复是真实有效的。** 两个 P0 级阻断（上海出发跨城失效、返程校验死循环）已修复并通过新用例验证；多人协作、文本回填抽取、ICS 时区、多人聚合等关键修复都是真改而非针对用例的补丁（换了数据依然成立）。测试套件 117 → 136 全过。

**两个视角并不矛盾**：后端能力在快速补齐，但前端没有同步——后端已经返回真人话 `reply`，前端仍渲染调试标签（web/index.html:311）。**用户不为"后端其实懂了"买单，只为界面上看到的东西买单。** 以用户可见结果为准，本轮结论是不通过。

**遗留三条硬伤**：① 假数据问题（P0-3）未动——餐饮仍是 3 家写死假餐厅、接驳仍是 20+i*5，北京计划照样推荐"本帮菜馆"；② 天气/提醒两条链路仍是死代码；③ 对话体验用户侧不合格：前端不渲染 reply，且意图/抽取仍有多个明确错误（C3/C4/C5/C6）。

## 三、Copilot 复测（全新话术，7 场景）

**用户视角结论：不通过。** 用户实际操作时，界面只回一行"（意图：X · 动作：Y）"调试文本（真实用户实测："本周末我和朋友要从上海去杭州看展" → 只回"（意图：ask_info · 动作：answer）"）。后端 API 层确有进步——同一句话在 API 三次复测均稳定返回正确意图 provide_constraints + 真人话 `reply` + 约束抽取——**但 `web/index.html:311` 把 `reply` 字段丢弃，只渲染调试标签**。前后端不同步，用户不可接受。

| # | 用户说（新措辞） | 结果 | 判定 |
|---|---|---|---|
| C1 | "俩人大后天从广州出发，玩两天，想吃好的逛逛博物馆，一个人预算一千左右" | 抽出 广州/博物馆/预算≤1000，回复自然；但 **"俩人"未更新 party_size（沿用旧值 3）、"大后天"未解析、"吃好的"（美食）漏抽** | ⚠️ |
| C2 | "周末不知道去哪儿玩好，给点灵感" | 诚实回复"库内暂无"+引导粘贴官方链接，不编造 | ✅ |
| C3 | "目的地换成西安吧" | **语义错误：把西安写成了出发地**（origins=["西安"]，回复"从西安出发"）——用户是要"去"西安 | ❌ |
| C4 | "莫奈那个展在哪儿办？门票多少？" | 答"库内暂无记录"——**但库内明明有"中华艺术宫 莫奈与印象派大师展"**，问答检索未命中已有数据 | ❌ |
| C5 | "酒店我订好了，全季上海人民广场店，这周五入住" | **误判为 chitchat**（"订好了"未命中"订了"关键词），酒店信息完全丢失 | ❌ |
| C6 | "周日好像要下暴雨，行程要不要调整？" | 未识别天气意图，当成普通约束处理 | ❌ |
| C7 | "帮我把预算改成两千" | 正确 patch budget_band.max=2000 | ✅ |

**核心 UI 缺陷（升级为对话不通过的主因）**：后端已返回 `reply` 字段，但 `web/index.html:311` 仍只渲染"（意图：X · 动作：Y）"调试文本——**用户在界面上看不到任何一句真人话回复，只能看到内部调试标签**。修复要求极低（渲染 `d.reply` 即可），未做即不应提测对话功能。

## 五、放行建议

**当前状态：主链路已可演示，但"诚实"底线被假数据和脏数据破坏，建议批次修复后复验。**

1. **必须修（放行前置）**：
   - P0-3 假数据三处：餐饮接真实 POI 或 UI 显著标注"示例数据"；接驳同理（N 轮验证已证明与地图无关）；
   - N1 数据质量：validator 增加 INVERTED_RANGE + 过期活动拦截（expired 六态里本来就有，没用上）；深研入库加时间合理性校验；
   - C3/C5 意图与语义错误："目的地换 X"≠出发地；"订好了"类回填意图词表扩充；
2. **应该修**：C4 问答检索命中库内已有活动；UI 渲染 reply 字段；import 落库（P1-6b）；N2 字段推导；
3. **可排期**：天气/提醒链路（P1-7/P1-8）；§06 bundle 字段补齐；C1 抽取质量（人数/相对日期/多兴趣）；N3/N4/P2 残留。

**给开发的反馈**：这轮修复质量高——P0 两项、多人、ICS、回填抽取都是真改，换用例后依然成立，136 项测试全绿。剩下的核心矛盾还是那个：演示数据与真实功能的边界。按 PRD 自己的标准——"未确认字段被错误展示为已确认的次数必须为 0"——假餐厅和倒序时间戳都是这条 KPI 的违规。
